## 1. Verdict

**PASS** for the automatic-upgrade gate, with five residual items recorded in section 1.2 and release-notes obligations in section 9. No item meets a section 0.3 stop condition: every persisted identifier that changed in this train has a deterministic, idempotent, backed-up mapping that this audit exercised, and nothing is deleted before its replacement is verified.

The one structural change of the train (issue #1901: family rows mount their real packages instead of `@linxin666/dsh-web-all/<family>` subpaths) rewrites a persisted profile identifier, and that is exactly what section 0.3 asks an audit to refuse. It qualifies only because the mapping is real and verifiable: the loader skip is proven in section 5, the repair that reverses it is proven in section 5, it runs on both the update path and the startup path (section 4), it is idempotent and takes a backup before it writes, and every old subpath export stays resolvable (section 6) so an unrepaired row degrades to "config not applied" instead of `ERR_PACKAGE_PATH_NOT_EXPORTED`.

## 5. Loader evidence for the row-name migration

Two facts must hold, and both were executed rather than argued. The loader is `@deepseek-ai/cordis-plugin-include@1.0.9` (`applyEntryPatches`, the same function the host runs), fed with the entry list parsed out of the packed aggregate `cordis.patch.yml` (21 entries):

```
$ node /tmp/dsh-verify-0_4_8-audit-probe/patch-probe.mjs
composed entries from the shipped aggregate layer: 21
--- stale name (0.4.7 profile row) ---
warn: [ 'patch: name mismatch for () (expected (), got ()), skipping "web-ui-task-board" "@linxin666/dsh-client-ui-task-board" "@linxin666/dsh-web-all/task-board"' ]
row disabled: undefined
row config: undefined
--- repaired name ---
warn: []
row disabled: true
row config: {"githubRepos":["acme/widget"]}
--- retired row left in profile (no prune) ---
warn: [ 'patch: entry () not found "web-ui-model-capabilities"' ]
```

Reading: a 0.4.7 profile row is skipped whole (source: `node_modules/.pnpm/@deepseek-ai+cordis-plugin-include@1.0.9*/src/index.ts:115-117`, `continue` after the warning), so both the user's `disabled` and the user's `config` stop applying for that boot, and a retired row overrides nothing. The repair is what turns the first case back into the second. Nothing is deleted, duplicated or rewritten into a second row in either case.

The repair is idempotent by construction: it writes only when a row's recorded name differs from the live name the installed bundle declares (`gateway.ts:1811-1831`, `rows.ts:444-460`), the write is `copyFile` to `.bak-plugin-manager` then `.tmp` + rename (`rows.ts:22-25`), and `packages/dsh-plugin-manager/tests/rows.spec.ts` pins the healthy-profile-no-write case.
