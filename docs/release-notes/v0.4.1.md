本次发布修复 0.4.0 的升级路径，共 1 项修复。

> **重要变更**：本版本没有需要手工迁移的改动，但**从 0.3.24 或更早版本升级的用户应当升到本版本**。0.4.0 声明的卫星依赖范围是 `^0.3.24`，升级时包管理器会保留锁文件里已经解析到的 `0.3.24`：那个构建仍然注入 0.1.7-rc.1 宿主已退役的 `settingsScope` 服务，皮肤中心、宠物与社区插件的浏览器半区会一直等它，因而永不激活。本版本把三个卫星依赖的下限提到 `^0.3.25`，锁文件不再满足新范围，升级时会重新解析到携带该迁移的 `0.3.25`。全新安装不受影响。

### 修复

- [aggregate] 卫星依赖下限提高到 `^0.3.25`，升级时不再保留 0.1.7-rc.1 迁移之前的卫星构建
- [aggregate] 在卫星行测试里钉住该下限：任何声明的范围都不得接受低于迁移版本的地板

<summary>English</summary>

This release fixes the 0.4.0 upgrade path. One bug fix.

> **Important change**: no manual migration is needed, but **anyone upgrading from 0.3.24 or earlier should move to this version**. 0.4.0 declared the satellite ranges as `^0.3.24`, and an upgrade keeps whatever version the lockfile already resolved, so the `0.3.24` build stayed installed: it still injects the `settingsScope` service the 0.1.7-rc.1 host retired, and the skin center, pet and community client halves wait for it forever and never activate. This release raises the three satellite floors to `^0.3.25`, so the lockfile no longer satisfies the new range and re-resolves the satellites to the `0.3.25` build that carries the migration. Fresh installs are unaffected.

### Bug Fixes

- [aggregate] raise the satellite dependency floors to `^0.3.25`, so an upgrade no longer keeps a satellite build from before the 0.1.7-rc.1 migration
- [aggregate] pin that floor in the satellite-rows lane: no declared range may admit a floor below the migration release
