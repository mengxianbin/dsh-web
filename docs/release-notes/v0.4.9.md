本次发布把 agent 真正能开的浏览器搬进右栏：新增 `@linxin666/dsh-client-ui-browser-view`，一个由 CDP 驱动的真实 Chromium，agent 用 `browser_navigate`、`browser_snapshot`、`browser_click` 这一组工具操作它，用户看到的就是它正在渲染的那一页；Chrome 懒启动，插件挂载时不会被拉起。家族新增两条行：`dsh-agents` 把 agent 小队做成可整队运行的真实会话（成员可钉 agent 预设、权限、模型与思考档位，成员简介进入该成员会话的系统提示），`dsh-message-edit` 可以改写一条纯文本消息、在前一个事件边界分叉并在新分支上重发。任务看板这一版把子任务交给父卡片派发，并把看板的能力面经 `dsh-task-board-remote` 绑到远程桥（`board.v1`），配对的手机读到的就是同一本账。远程桥继续沿协议 v1 扩张：用量台账（`usage.v1`、`usage.stats.v1`）、工作区与会话管理写方法（`workspace.v1`、`session.admin.v1`）、斜杠指令（`commands.v1`）、小队（`squads.v1`）、待答提问对账（`questions.list.v1`）与推送通道（`push.v1`，含 APNs 发送器与实况卡）。宿主下限一并抬到 `0.2.1-rc.3`，与 CI 钉住的 DSH 版本同版。

> **先升级 DSH，再升级本包**：聚合包的 `dsh.engines.dsh` 与 peer 依赖 `@deepseek-ai/dsh` 一起从上一版本线抬到 `>=0.2.1-rc.3`，与 CI 固定的 `DSH_CLI_VERSION` 0.2.1-rc.3 同版。DSH 低于该版本的宿主会因引擎门跳过家族行——症状是插件在面板里消失，而不是报错，所以先升级 DSH，再升级本包。需要回滚时回装 `@linxin666/dsh-web-all@0.4.8`。
> **会真正迁移的入口只有一个**：本仓已没有 Doctor 启动前迁移路径，`dsh-doctor` 现在只是 tombstone，装不上也没有启动前置消费者。唯一具备预检、版本断言与回滚的路径是插件管理器更新（含旧聚合名 `@linxin666/dsh-web-ui-all` 的迁移分支）；直接 `dsh web` 不执行安装，也不做任何预检，旧 profile 会原样保留。手工恢复用 `dsh plugin --profile <name> add @linxin666/dsh-web-all@0.4.9`。
> **本版没有删除或重命名任何持久化或线协议标识符**：设置 section id、配置 key、localStorage 键、控制面 API path 与聚合行 id 全部保持原值。新增的都是纯增量：聚合行多出 `web-ui-agents`、`web-ui-message-edit`、`web-ui-browser-view`、`web-ui-task-board-remote` 四行，远程桥多出 `usage.v1`、`usage.stats.v1`、`workspace.v1`、`session.admin.v1`、`commands.v1`、`questions.list.v1`、`squads.v1`、`push.v1` 八个能力位。
> **未钉工作区的卡片不再运行**：卡片解析不到工作区时直接拒绝，不再静默落进 profile 目录。旧卡片若没钉过工作区，要补一个工作区才能跑。

This release moves a browser the agent can actually drive into the right dock: the new `@linxin666/dsh-client-ui-browser-view` package runs a real CDP-driven Chromium that the agent operates through `browser_navigate`, `browser_snapshot`, `browser_click` and their siblings, so the page the user watches is the page it is rendering; Chrome starts lazily and is not launched when the plugin mounts. The family gains two rows: `dsh-agents` turns agent squads into real sessions that run as a whole squad (a member pins an agent preset, a permission, a model and a reasoning level, and its brief joins that member session's system prompt), and `dsh-message-edit` rewrites a text-only user message, forks at the preceding event boundary and resends on the new branch. The task board hands subtask dispatch to the parent card in this version, and its capability face is bound to the remote bridge through `dsh-task-board-remote` (`board.v1`), so a paired phone reads the same ledger. The remote bridge keeps extending protocol v1: usage statistics (`usage.v1`, `usage.stats.v1`), workspace and session-management write methods (`workspace.v1`, `session.admin.v1`), slash commands (`commands.v1`), squads (`squads.v1`), reconciliation of held questions (`questions.list.v1`) and a push channel (`push.v1`, with an APNs sender and live cards). The host floor moves to `0.2.1-rc.3`, the same version CI pins.

> **Upgrade DSH first, then this package**: the aggregate's `dsh.engines.dsh` and its `@deepseek-ai/dsh` peer dependency both move from the previous line to `>=0.2.1-rc.3`, the version CI pins as `DSH_CLI_VERSION` 0.2.1-rc.3. A host below that version skips the family rows at the engine gate — the symptom is plugins disappearing from the panel rather than an error — so upgrade DSH first and this package second. To roll back, reinstall `@linxin666/dsh-web-all@0.4.8`.
> **Only one entry point really migrates**: this repository no longer has a Doctor pre-launch migration path; `dsh-doctor` is only a tombstone today, it cannot be installed and no launcher consumer exists. The plugin-manager update (including the legacy aggregate-name `@linxin666/dsh-web-ui-all` migration branch) is the only path with preflight, version assertion and rollback; a direct `dsh web` performs no install and no preflight, so an old profile stays exactly as it is. To recover by hand, run `dsh plugin --profile <name> add @linxin666/dsh-web-all@0.4.9`.
> **This version deletes or renames no persisted or wire-protocol identifier**: settings section ids, configuration keys, localStorage keys, control-plane API paths and aggregate row ids all keep their values. Everything new is purely additive: the aggregate gains the rows `web-ui-agents`, `web-ui-message-edit`, `web-ui-browser-view` and `web-ui-task-board-remote`, and the bridge gains the capability bits `usage.v1`, `usage.stats.v1`, `workspace.v1`, `session.admin.v1`, `commands.v1`, `questions.list.v1`, `squads.v1` and `push.v1`.
> **A card without a pinned workspace no longer runs**: when no workspace resolves, the card refuses instead of quietly landing in the profile directory. A card that never pinned one needs a workspace before it can run again.
> **A forwarded request is no longer treated as loopback**: the remote face and the shared layer decide loopback in layers, an upstream request that was forwarded counts only when it is explicitly declared trusted, and the task board additionally admits Host connection-authenticated proxy requests ([#1930](https://github.com/zhu1090093659/dsh-web/issues/1930)). A reverse-proxy deployment must switch that trust on in its configuration, or its requests are refused as external.
> **A new package's first release**: `@linxin666/dsh-client-ui-browser-view` did not exist on npm before; it debuts at `0.4.9` and ships with the aggregate in this version, and gives the aggregate a browser tab the agent can drive. It starts lazily — mounting the plugin does not launch Chrome, the first real browsing action does — so an install costs no process.
> **A freshly published version may be held back by pnpm's release age**: with `minimumReleaseAge` enabled (24 hours by common default), an update that runs right after the satellite packages publish is refused outright. The remedy is `minimumReleaseAgeExclude` for `@linxin666/*` in the profile's `pnpm-workspace.yaml`, or waiting the window out before updating.
> **The satellite ranges move in the same batch**: the four satellite repositories publish `0.4.9` first, and only once the registry resolves them does the aggregate's dependency range move from `^0.4.8` to `^0.4.9`:
> - Skin center (`dsh-skins`): `@linxin666/dsh-client-ui-skin-center@0.4.9`
> - Pet (`dsh-pet`): `@linxin666/dsh-pet@0.4.9`
> - Community plugin index (`dsh-community-plugins`): `@linxin666/dsh-client-ui-community-plugins@0.4.9`
> - Preset center (`dsh-presets`): `@linxin666/dsh-client-ui-preset-center@0.4.9`
