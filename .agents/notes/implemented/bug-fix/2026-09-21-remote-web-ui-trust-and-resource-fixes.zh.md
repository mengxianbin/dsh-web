# Agent Note: remote-web-ui 信任与资源修复

Status: implemented

## Problem

对 `packages/dsh-remote-web-ui` 的一次只读审计（host 信任/凭据面、host 运行时、浏览器半区、客户端/服务端契约）加上针对线上处理函数的实测，发现了有具体代价的缺陷：

1. `requirePairingForLan: false` 时，`/remote` 前缀会代理每个请求到回环，并附上进程自己的 `dsh-auth-*` 凭据——即以机器所有者身份授权的凭据。任何能触达端口（局域网绑定、快速隧道、中继）的客户端都能在未配对的情况下驱动完整 host API，而配置文案只承诺桌面继续走裸 `/api`。
2. accept 限流对回环来源的请求以 `X-Forwarded-For` 的**第一个** hop 作为键——而该值由客户端控制（边缘是追加而非替换）——因此轮换该请求头即可为每个请求铸造新的爆破预算。该表也没有硬上限，同样的轮换会让它无界增长。用轮换键在线上处理函数实测：前 2 000 个请求平均 0.067 ms/请求，30 000 个请求中最后 2 000 个为 0.152 ms（2.3 倍，单调上升）；RSS +41..44 MB。
3. 竖屏适配层把每个被压制的会话/项目行记录在一个仅在 revert 时清空的 `Map` 里。React 会重建行节点，因此脱离文档的子树在页面生命周期内始终可达；带强制 GC 的 WeakRef 探针确认了这种保留。
4. 同一轮审计在第一轮之外还确认了更多缺口：命名隧道的账户令牌出现在子进程 argv 中（隧道存活期间任何本机用户都能通过 ps/proc 读到）；无法通过校验的 cloudflared 二进制会在每轮重启时重新下载整个平台压缩包；`GET /api/update/status` 在每次 GUI 页面加载时对每个家族包各发一次 registry 探测且无缓存；清单里的包名未经校验就进入 win32 更新命令行；POSIX 更新超时只向直接子进程发信号，pnpm 的生命周期脚本孙进程继续运行；更新输出按 `data` 事件逐块解码（会切断多字节字符）；关闭插件后 cloudflared 子进程与中继注册仍在运行；从快速隧道切到命名模式后，已失效的快速主机仍作为二维码基址；姿态探针把 harness 的 401 报成「/api 通道敞开」；未配对的 status 调用方能拿到本机私有局域网地址；浏览器半区在每个 600ms tick 里为同样的官方节点反复全文档查询；每次 `touchstart` 都会为几乎不会触发的滑动否决强制样式重算与布局；视口变小时不会重新夹取小鲸鱼；禁用适配层后全局 `focus` 补丁从未移除；`attach()` 会就地修改调用方持有的 `Headers` 并写入设备凭据；局域网绑定卡片从手机会永久轮询仅限回环的端点；二维码符号在每个 SSE 帧上重建；以及一个状态机根本无法产生的「已被使用」accept 码（409）仍被文档化与渲染。
5. 更小的已确认缺口：面板会在 `revoke`/`stop` 被拒时乐观地移除设备行（并把「停止」翻到已停止阶段），而服务端会话仍然存活，且服务对「什么都没改变」的请求不发状态变更，因此这种虚假保证可能一直保留；设备凭据被只写不读地复制进 `localStorage`（无人读取、无过期）；`publicBaseUrl` 末尾斜杠会铸造无法路由的 `//pair-accept` 链接；`/pair-app` 应用壳拉取从不丢弃过期内部凭据（重启前所有配对都 502）；心跳会对永久 401/403 无限轮询；win32 更新超时路径上的 `taskkill` 未挂 `error` 监听；浏览器回环判定缺少 host 侧已接受的方括号 `[::1]` 写法；`isTrustedHost` 遇到畸形可信主机项会抛错；以及文档与实现语义矛盾（「一次性」令牌在其窗口内可重复配对；空闲默认值写成 7 天而实际为 30 天）。

## Decision

- **进程内部浏览器认证凭据只随「已出示有效配对设备凭据」的请求发送。** `/remote` 的 HTTP 与 WebSocket 处理都先解析设备凭据，只有其有效时才传入 `deps.auth`。关闭 `requirePairingForLan` 时通道仍会代理过期同源改写（不返回 403），但未配对的调用会被转发而不带该凭据，内层路由返回 401。配置 JSDoc 与中英 README 安全模型均已说明。
- **accept 限流只信任边缘追加的 XFF hop，并有硬上限。** `rateLimitAccept` 取请求头的**最后一个** hop（边缘追加它看到的地址；更早的 hop 由客户端提供），`acceptLimitKey` 将其截断到 64 字符。桶表由 `MAX_ACCEPT_BUCKETS`（1024）限制并按 FIFO 驱逐；过期改为摊销：从按插入序排列的表头开始清理，因为重新起窗的桶会重新插入到表尾，所以每请求 O(1)。
- **适配层会遗忘 React 已脱离文档的行。** `disableRowDrag` 对任何已不再连接但仍在跟踪中的行写回记录的 `draggable` 状态并删除该条目，因此表内只保留存活行；`restoreRowDragState` 与 revert 路径共用。
- **公网地址在进入服务时规范化为其 origin**（`PairingService.setPublicBaseUrl` 经 `canonicalBaseUrl`），末尾斜杠或路径因此不会铸造无法路由的 `//pair-accept` 链接。
- **设备凭据仅限会话作用域。** `/pair-app` 捕获脚本只写入 `sessionStorage`；从不被读取的 `localStorage` 副本已删除。
- **被拒的撤销或停止不会改动面板名单。** `RemoteEntry` 只在请求成功后应用乐观的阶段/名单变更，因此 403 或网络失败会保留服务端权威的设备行，而不是声称一次并未发生的撤销。
- **当服务器证明永远不会接受该页面时停止轮询。** `sendHeartbeat` 返回响应状态，`shouldStopHeartbeat`（401/403）清除 10 秒定时器；瞬时错误保持原节奏。
- **其他正确性修复**：应用壳拉取在 401/403 时丢弃过期内部凭据；win32 `taskkill` 子进程挂上 `error` 监听；浏览器回环判定（及引导脚本守卫）接受 `[::1]`；`isTrustedHost` 忽略无法解析的可信主机项而不是抛错；删除只写不读的 `consumed` 令牌标志，并把自相矛盾的 `accept()` 注释改为「窗口内始终可作凭据」的语义；空闲默认值文档改为 30 天。

- **命名隧道令牌经 `TUNNEL_TOKEN` 传递，而非 `--token`。** 包的 spawn 包装会继承环境变量，因此 `withTunnelTokenEnv` 只在真正派生 cloudflared 的构造调用期间设置该变量，随后立即恢复原值；子进程保留自己的副本。`namedTunnelArgs()` 不再接收令牌。
- **无法运行的二进制不会被无限重新下载。** `createBinaryReadiness` 将每个进程的安装尝试上限设为 `MAX_BINARY_INSTALL_ATTEMPTS`（3），之后重新抛出记住的失败；瞬时安装错误仍有重试机会。
- **更新状态探测被记忆化（60 秒 TTL）并共享在途请求**，一次完成的更新会使其失效；更新后的校验仍直接调用 `checkUpdates`，不会读到陈旧结果。
- **包名在进入更新命令行之前先校验**（`SHELL_SAFE_PACKAGE_RE`），因此带 shell 元字符的清单键会被丢弃，而不是在 win32 上被拼接。
- **POSIX 更新超时会杀掉进程组**：子进程以 detached 方式启动（自成组长），`killImpl(-pid, 'SIGTERM')` 可触达 pnpm 的孙进程，组已消失时回退为直接 kill。
- **更新输出按候选进程解码一次**，改用共享的有界 `createOutputCapture`，不再逐 `data` 事件解码。
- **禁用插件同时关闭公网入口**：`sync()` 在 `enabled === false` 时调用 `tunnel.stop()`、`disposeRelayRegistrar()` 与 `publicBase.reset()`；中继注册行保留，重新启用即复用同一源。
- **命名模式在隧道运行前就发布其固定主机名**，因此命名启动失败不会把上一个快速主机留作二维码与栅栏基址。
- **无法落盘的撤销会删除过期设备库**（`persistRevocation`）：否则写入失败的旧文件会在下次启动被原样恢复，静默撤销失效。
- **姿态探针把 harness 的 401 视为已受门控而非敞开**（围栏已通过、浏览器认证拒绝）；只有既非 403 也非 401 的状态才算 exposed。
- **未配对的 status 调用方不再收到私有局域网地址**；回环桌面与有效配对 cookie 仍可见。
- **移除已死的「已被使用」accept 码**：`AcceptResult` 只携带 `invalid`（未知、过期或已停止），客户端把历史 409 映射为同一拒绝，面板文案改为真实窗口（「限时链接；在过期或刷新二维码前可为多台设备配对」）。zh/en/ru 同步更新。
- **浏览器半区不再做逐 tick 的全文档工作**：官方节点经 `isConnected` 失效的缓存解析（每 tick 7 → 1 次全文档扫描），缺失的选择器不再每 tick 重走文档（见下方负缓存），横向可滚动滑动否决改为在抬手时判定而非每次 `touchstart`，视口变化时重新夹取小鲸鱼（revert 时重置其显示状态），禁用适配层时移除全局 `focus` 补丁（启用时重新安装）。
- **`attach()` 复制调用方持有的 `Headers`** 而不是就地修改，因此设备凭据不会随通道未改写的请求外泄；二维码符号按链接记忆化；局域网绑定轮询在 401/403 时停止（`shouldStopLanBindPoll`），不再对仅限回环的拒绝永久重试。

- **适配层的「选择器缺失」按 DOM 而非时钟缓存。** 缺失是常态而非例外（适配层自己不持有任何 overlay；tabs 行、tools 行、侧栏行在某一时刻本就可能不存在），而每 600 ms tick 都为同一个缺失选择器重走一遍会话规模的文档，几乎总是解析为 null。已知缺失的选择器现在会跳过，直到文档 `MutationObserver` 报告「挂载内容发生变化」——任意位置的子节点列表，以及被缓存选择器匹配的 `class` 与 `data-dsh-frame` 属性。观察器排除 `<body>` 上的写入：适配层每 tick 切换三个 body class，把它们计入会让缓存每 tick 失效，反而把被删掉的扫描请回来。因此后出现的界面仍在下一个 tick 内被发现，与改动前的无条件探测延迟相同。
- **侧栏行扫描限定在缓存的侧栏根内。** 两个行选择器都要求一个 `_sidebarCol` 祖先，所以被替换掉的全文档扫描本就只可能返回该根内的行。实测：稳态下每 tick 的 1 次文档 `querySelector` 与 1 次文档 `querySelectorAll` 归零。
- **设备凭据不再进入内层回环再发起请求。** `?device=<id>` 之所以出现在外层 WebSocket 握手上，是因为握手无法携带请求头，而升级路由正是在那里校验它；继续向内转发等于把一枚实时会话凭据写进源站自己的请求行与访问日志。该参数已从内层路径移除，其余查询参数原样透传，内层网关 mux 只按路径匹配。
- **posture 帧纳入快照比较**（`snapshotsEqual`/`postureEqual`），且比较能容忍形状不符的帧。一轮探测可能在其余所有字段都不变的情况下改变该帧——这是常见情形：设置在变、隧道进入 running 都会重跑探测，快隧道重启还会换掉被探测的主机集合。把它排除在 `snapshotsEqual` 之外会抑制这些发射，使回环 SSE 流与桌面面板在 phase 与名册不变期间停留在过期的暴露判定上。由于该比较运行在发射路径内、位于监听器错误隔离之外，null 帧或 hosts 数组中的 null 元素现在降级为「已变化」，而不是从产生它的 setter 抛出；这两种形状虽在类型之外，但手工构造的 host 纤维上下文可以传入。

## Alternatives considered

- **恢复真正的一次性令牌**（让 `accept()` 返回既有的 `used` 码并回 409）。否决：窗口内可重复配对是为跨 cookie 上下文的移动流程（相机预览 → 应用内浏览器 → 系统浏览器）刻意做的让步，且测试已固定该行为。错误在于文案与代码注释，因此改为修正它们；`used` 作为旧版或第三方 host 仍可能返回的分支保留在 wire 契约中。
- **继续以第一个 XFF hop 作为限流键**，依赖令牌熵。否决：限流是配对端点唯一的未认证洪水约束，键由调用方控制会让它形同虚设，同时仍然消耗内存。
- **关闭策略时仍要求 `/remote` 配对**（回 403 而非 401）。否决：关闭策略模式的既定用途就是让过期的同源改写继续可用，403 会直接破坏它；不发放凭据既保留既定行为，又消除了机器所有者访问。
- **缓存应用帧并把适配 tick 的查询根植于它**（每 600 ms tick 的 7 次全文档扫描中的 5 次）。以「侧栏行扫描限定作用域」的形式部分落地，但完整版本仍被否决：把每个选择器都改根会把匹配集合一起改掉，这必须在真实 GUI 上做一轮浏览器 QA，tick 无法替代。只有行扫描改了根，因为它那两个选择器本就要求一个 `_sidebarCol` 祖先。
- **用「按 tick 计数 TTL」让负缓存失效。** 收益实测相同但被否决：它会让后出现的界面要等 TTL 才被发现，直接顶破了既有 5 个测试的收敛窗口，也会把侧栏折叠与表头落座从 1 个 tick 拉长到 3 个。DOM 变化信号在稳态下不花任何代价，且把发现延迟保持在 1 个 tick，与改动前完全一致。
- **一次性 WS 票据替代 `?device=<id>` 查询串。** 已设计但未落地：票据必须以同步方式到达引导补丁（由服务端渲染），mux 会在其 TTL 之后重连，而整条手机传输都依赖该 socket——改错会直接破坏配对，且没有真机无法验证。本轮只从内层回环再发起中剥离该查询串，并在安全模型中记录残留；票据仍是计划的替代方案。
- **用磁盘上的 `--token-file` 承载命名隧道令牌。** 否决，改用 spawn 时环境变量：令牌文件需要创建/删除生命周期，进程异常退出还会留下持久密钥；而环境副本只存在于必须持有它的子进程。
- **端到端删除 `used` wire 代码。** 第二轮在文案对齐后已完成：状态机无法产生它、本 cohort 也没有 host 会发送它，保留该分支只会让面板宣称一个并不存在的一次性令牌。历史 409 在客户端仍降级为 invalid 拒绝。客户端映射与其文案是「host 确实回 409」时的优雅路径；在没有对应故障需要修复的情况下删除它属于 wire 契约变更。

## Consequences

- 关闭配对策略的运维者不再获得静默的机器所有者旁路，但此类部署上过期的客户端改写现在会看到 harness 的 401，而不是可用的代理。这正是文档化的「裸 `/api`」模型，并已在安全模型中说明。
- 在持续的轮换键洪水下，限流可能驱逐合法桶并重置该客户端的窗口。无论何种情况，令牌猜测都不可行（128 位令牌）；该上限换来的是有界内存与平坦的每请求成本。
- 脱离文档的行会保留其官方 `draggable` 状态直到下一个 600 ms tick，而不是直到 revert；该 tick 在适配层激活期间本就在运行。
- 撤销后心跳不再刷新在线状态，因此被撤销的手机会立即不再计入在线，而不是每 10 秒一次。

## Testing

- `tests/remote-api.spec.ts`：关闭策略时，未配对请求不带（也从不兑换）进程凭据；有效配对设备仍会带上。
- `tests/routes.spec.ts`：轮换的前置 XFF hop 因最后一个 hop 而落入同一限流窗口；末尾斜杠公网地址铸造可路由的二维码 URL；畸形可信主机项被忽略。
- `tests/pair-api.spec.ts`：心跳状态被回传，停止判定仅限 401/403。
- `tests/remote-entry.spec.tsx`：被拒的取消配对会保留设备行（该测试在修复前的乐观变更下失败）。
- `tests/mobile-adapt.spec.ts`：脱离文档的行不再被跟踪；该 spec 会清理新模块实例启动的定时器，避免陈旧适配层跨用例干扰。
- 实测（同一脚本、30 000 个轮换键、每版本三次）：基线 0.067 ms 升至 0.152 ms/请求，RSS +41..44 MB；修复后 0.059 ms 降至 0.041 ms，无增长趋势。RSS 差值仍由请求churn 主导，本身不构成证据；表的界由构造保证。
- 选择器改造的实测（headless Chromium，4 倍 CPU 节流，36 156 个已挂载节点，18 秒窗口，三次取中位数，改动前后分别打包为独立 bundle）：稳态 tick 的 DOM 开销从 4.31-4.50 ms/tick 降到 0.00 ms/tick（每 tick 文档查询 1 + 1 降到 0 + 0）。在会话持续插入（流式回答，每 250 ms 一个节点）下，同一测量为 4.23-4.62 ms/tick 降到 1.27-1.42 ms/tick（-69%）：此时文档变化信号会不断让缓存重新武装，所以这个数字是行作用域收敛带来的，不是缓存的。调查期间得到的两个 jsdom 数字全部弃用——它把每节点成本放大约两个数量级，与 Blink 不可比。
- 边界写明而非暗示：收益在会话空闲或只聚焦单个会话时最大，在长会话持续流式输出时最小。
- `tests/remote-upgrade.spec.ts`：内层握手路径不再携带设备凭据，且调用方自己的查询参数仍原样透传。
- `tests/pairing.spec.ts`：posture 轮次会到达状态订阅者，完全相同的重复不会，判定变化会。
- `tests/mobile-adapt.spec.ts`：适配层激活期间出现的 overlay 在下一个 tick 内被采纳；revert 期间出现的表头在重新启用后第一个 tick 内落座——该用例在两个 clear 都被移除时会失败（变异验证）。
- `tests/pairing.spec.ts`：posture 轮次会到达状态订阅者，完全相同的重复不会，判定变化会；null 帧 / hosts 中的 null 元素降级为「已变化」而非抛出（最后一项在移除形状守卫后失败）。
