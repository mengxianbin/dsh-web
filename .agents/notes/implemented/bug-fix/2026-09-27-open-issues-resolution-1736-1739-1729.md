# Agent Note: Open Issues Resolution (#1736, #1739, #1729)

Status: implemented

## Problem

Three actionable issues were open and verified:

1. **#1736**: In `dsh-skill-explorer` (and `dsh-ssh`), the panel header's "‹ back to conversation" button (`data-dsh-center-view-back`) was completely unresponsive. The client entry omitted `layout` from its `inject` declaration, so Cordis strict access caused `ctx.get('layout')` to return `undefined`. As a result, `controller.close()` calling `layout.selectPanel(null)` was a silent no-op, and active panel synchronization was never wired.
2. **#1739**: In `dsh-usage`, `readNamespace` invoked `settings.get(ns)`, which was removed in DSH 0.1.7 where `settings` is `SettingsForms`. The call threw a TypeError and was silently swallowed by catch, returning `undefined`. Consequently, any `pi-ai` provider configured via `apiKeyEnv` in profile patches (such as `opencode-go` or `zai`) evaluated to `credential: "none"`, completely breaking balance and quota window probing.
3. **#1729**: In `dsh-task-board`, when the Host's same-origin loopback fence rejected a request with 403 `{"ok":false,"error":"forbidden"}`, `HttpTaskBoardHostTransport` mapped it onto `board.hostError.unauthorized` ("This session is no longer signed in; reload the page and try again"). This misleadingly pointed operators toward user authentication or session expiration rather than origin / cookie stripping by desktop shells or reverse proxies.

## Decision

1. **Skill Center & SSH Panel Navigation (#1736)**:
   - Added `layout` to `export const inject` in `packages/dsh-skill-explorer/src/client/index.ts` and `packages/dsh-ssh/src/client/index.ts`.
   - Guarded `ctx.get('layout')` calls and verified that `controller.close()` correctly dispatches `layout.selectPanel(null)` to return to the active conversation view.
   - Added unit test coverage verifying the inject declaration and navigation behavior.

2. **DSH 0.1.7 Configuration Resolution & Volatile Unwrapping (#1739)**:
   - Enhanced `readNamespace` in `packages/dsh-usage/src/host/usage-service.ts` to probe:
     1. Legacy `settings.get(ns)` when available;
     2. DSH 0.1.7 `SettingsForms.describe({ redactSecrets: false })` matching `d.ns === ns` or provider descriptor shapes;
     3. Active loader entries from `ctx.root.loader` or `ctx.loader`;
     4. Profile configuration rows from `configEditor.configuration()`.
   - Added `unwrapVolatiles` to recursively unwrap Cosmokit / Cordis `Volatile` references and `ConfigRef` getters.
   - Added `routeBaseUrl` to apply origin matching checks (`balanceAppliesToRoute`) for both `pi-ai` and custom `deepseek` routes.
   - Added unit tests covering `settings.describe()` with volatile unwrap, `configEditor` fallback, and custom deepseek `baseURL` balance exclusion.

3. **Task Board Fence Rejection Error (#1729)**:
   - Added `forbidden` to `HostApiFailure` in `packages/dsh-task-board/src/client/host-api.ts`.
   - Separated 403 `forbidden` (fence rejection) from 401 `unauthorized` (session expiration).
   - Added dedicated `board.hostError.forbidden` localized strings in `zh` and `en` in `packages/dsh-task-board/src/client/locales.ts`, and mirrored the Russian translation in `packages/dsh-i18n/src/client/ru/task-board.ts`.
   - Updated unit tests in `tests/host-api.spec.ts`.

4. **Cross-Platform Path Normalization**:
   - In `packages/dsh-plugin-manager/src/host/profile.ts`, updated path split checks to match both forward and backward slashes, and normalized paths before comparison so POSIX test fixtures run deterministically on Windows.

## Consequences

- Clicking "‹ back to conversation" in the skill explorer closes the native center panel and smoothly restores the conversation view.
- Under DSH 0.1.7, `dsh-usage` resolves `apiKeyEnv` declared in profile patches and correctly surfaces balance and coding plan quota windows without requiring manual credential records.
- Operators seeing 403 fence rejections on the task board receive explicit diagnostic text explaining that same-origin / loopback checks were not met, distinguishing it from an expired login session.
