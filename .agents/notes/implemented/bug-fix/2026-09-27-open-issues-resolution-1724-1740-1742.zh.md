# Agent Note: 未结 Issue 综合解决（#1724, #1730, #1732, #1740, #1742）

Status: implemented

## 问题

在 #1728/#1741 已随 0.4.3 修复之后，仍有五条 Issue 具备可执行结论，其中两条来自家族维护者本身，另两条是上游转交的报告：

1. **#1740** ——「工坊订阅的皮肤在 设置-皮肤 中不显示」：`bootSkinRuntime` 把 `dsh-skin-applied` 窗口监听的移除函数放进了 `emit()` 会遍历的那个 `Set`，于是首次 `emit()`（初始目录加载）就执行了监听器自己的移除逻辑，此后整页都不再响应。而 `dsh-market` 工坊卡片安装完皮肤后正是通过该事件宣告的，因此安装永远无法在已打开的页面上生效，只能靠刷新。同一处启动逻辑还假定「持久化选择只会影响下一次页面加载」；当皮肤中心自己的偏好行变成官方设置行之后，这个假定不再成立：表单写它、宿主应用它，运行中的页面收不到任何通知。

2. **#1730** ——「第二实例账本锁冲突被透出为 not-mounted，且重启建议不成立」：`apply` 阶段抛错的插件行从未被记为 degraded，于是 `/api/dsh-web-all/degraded` 返回 `{"ok":true,"degraded":[]}`，而 `/rows` 仍列出该插件。任务看板只能看到一个未注册的路由族（宿主 webserver 的纯文本 404），于是把它翻译成 `board.hostError.notMounted` 并建议「重启 DSH 服务」——而锁在另一个进程手里，重启不可能有效。

3. **#1732** —— 转交自 `dsh-deep-whale#157`：ORCA LINK 小人舞台宣称的「新会话」区域远大于原生按钮的命中盒；只有被标记的行会被推到舞台下方（官方「插件」行没有第三方图标标记，因此留在舞台内）；图标晚于语义适配器首轮扫描挂载时，其父行不会被重新标记。

4. **#1742** —— 转交自 `dsh-deep-whale#159`：maid-atelier 的 body 级顶部花边（76px 绝对定位色带）盖住了官方插件管理页头部，使「返回插件列表」的面包屑不可见。

5. **#1724** —— 在任意皮肤中心视觉生效时，悬停发送箭头会让整个会话周期性上下跳动。官方 tooltip 渲染在输入卡内部且是 `position: fixed`；而中性化规则给 `[data-composer-card]` 挂了 `backdrop-filter`，非 none 的 `backdrop-filter` 会让该元素成为其 fixed 后代的**包含块**。气泡于是按卡片的坐标系解释「视口坐标」，落到卡片之外、却仍在会话滚动容器内，使 `scrollHeight` 增加约 1075px，每次悬停都把滚动夹到新底部（输入卡顶部 1164 -> 89），tooltip 卸载后再弹回：60 秒内 82 次跳变。

## 决策

1. **运行时 store 拥有 applied-skin 契约（#1740）**：`SkinRuntimeStore` 现在自带 `doc` / `window` / `apiBase` / `fetchImpl` 四个座位，任何运行时路径都不再触碰全局对象；`bootSkinRuntime` 在自己的 teardown 集合里注册 `trackSkinAppliedEvents`（`listeners` 与 `teardowns` 分离，合并二者正是缺陷本身）。`watchPersistedSelection` 在文档可见时以 2s 周期轮询 `/api/skin-center/v2/active`，用当前选择作为基线种子（避免开机重复激活），忽略已应用的值，且从不回写选择。客户端激活经 `ctx.effect` 安装它，因此清空插件行会连同监听器与计时器一并回收。若宣告的皮肤尚未出现在目录快照中，先执行一次 `refreshCatalog()`。
2. **apply 阶段抛错的行必须被记为该行 degraded，并让看板说出原因（#1730）**：`packages/dsh-web-all` 记录失败原因并对外暴露，家族状态路由因此返回真正的原因而不是空清单；`packages/dsh-task-board` 读取该详情，把「路由未注册」（404）与「另一个进程持有账本」区分开，并报出占用者 pid 与真正可执行的处置。账本仍保持「一个账本一个宿主」：不削弱锁，也不引入跨进程写入。
3. **装饰向它所覆盖的页面让位（#1742）**：maid-atelier 顶部花边在会话区保留原有色带，在官方插件管理页占据中栏时隐藏；锚点取官方的 `data-plugin-panel` / `data-plugin-detail` 属性，不使用任何哈希类名。抬高页面反而会遮住皮肤自身的装饰，因此让位的是装饰。
4. **ORCA 舞台定位的是原生面板列表而非逐行（#1732）**：整个 `nav` 列表被移到舞台下方，官方「插件」行与所有第三方行一起下移；新会话装饰获得命中面而导航仍可点击；语义适配器在相关后代或属性迟到时重新锚定父行，而不再只依赖整轮扫描。
5. **输入卡磨砂不得建立包含块（#1724）**：磨砂改由按输入卡尺寸跟随的 body 级跟随层（`data-dsh-composer-frost`）绘制，且任何规则都不允许再把 `backdrop-filter` / `transform` / `filter` / `contain` / `perspective` 挂回 `[data-composer-card]`。`--dsh-input-card-blur` 设置继续驱动同样的视觉强度。该机制、其备选方案与覆盖缺口由 dsh-skins 的 [输入卡磨砂改挂跟随层](https://github.com/zhu1090093659/dsh-skins/blob/main/.agents/notes/implemented/bug-fix/2026-09-27-composer-frost-follower-and-realm-safe-element-tests.md) 拥有——本批次只记录 #1724 已随其落地。

## 后果

- 在工坊安装皮肤会立刻作用于用户正在看的页面；在任何地方改动的选择都能在不刷新的情况下收敛。
- 第二个 DSH 实例会报出持有任务看板账本的进程以及可行的处置方式，而不是给出无效的重启建议。
- 皮肤不再遮住官方插件管理的返回入口，ORCA 小人舞台不再吞掉或错放导航，任何皮肤中心视觉都不会再让会话跳动。
