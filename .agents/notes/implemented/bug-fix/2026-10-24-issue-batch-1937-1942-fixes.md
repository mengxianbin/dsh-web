# Agent Note: Issue batch 1937-1942 — spend display currency, preset row removal, installer retries, and the pairing fence

Status: implemented

This note owns the four fixes shipped on 2026-10-24 for issues #1937, #1940, #1941 and #1942. The pairing-fence change also updates its owning note, [shared pairing trust fence](../simplification/2026-08-26-shared-pair-access-fence.md); the rc.3 cohort move is owned by [SDK cohort 0.2.1-rc.3](../architecture/2026-10-24-sdk-cohort-0.2.1-rc.3.md).

## Problem

Four open issues named defects that each came from one wrong assumption baked into a constant or a copy:

1. **#1940 — the liangshen preset could not mount on 0.2.1-rc.3.** The preset declared a `@deepseek-ai/dsh-tool-subagent-control/list-agents` row. rc.3 removed that subpath export (`exports` now carries only `.`) and registers `list_agents` from the control row's own `apply()`, so every liangshen session failed with `tool-subagent-list-agents ... never started`.
2. **#1941 — the Workshop installer could not complete an install.** One fetch had a hard-coded 30 s budget, no retry, and reported a Cloudflare managed challenge as a bare `manifest fetch failed: 403`. The published manifest alone is ~190 KiB and measured 68.5 s on a direct connection, so a healthy download looked like a hang.
3. **#1937 — every spend figure was hard-coded to CNY.** The client concatenated `¥` in three places while the ledger stores a CNY estimate, so an operator billing in USD read a number that did not match their invoice.
4. **#1942 — the trust fence threw on an un-injected service.** Documented in the fence note: the property fallback raised `cannot get property "remoteWebUiPairing" without inject` on every non-loopback request of a plugin that only injects `webServer`.

## Decision

1. The `tool-subagent-list-agents` row is deleted from `packages/dsh-liangshen/presets/liangshen/agent.cordis.yml`, replaced by a comment that says why it must not come back: rc.3 exports only the package root, and the control row registers `list_agents` itself.
2. `packages/dsh-market/src/core/installer.ts` fetches through one `fetchAsset()` policy. The per-attempt timeout defaults to 120 s (`FETCH_TIMEOUT_MS`), with `DEFAULT_INSTALL_RETRIES` (2) exponential backoff on timeouts, transport failures, 408, 429 and 5xx; a Cloudflare challenge (`cf-mitigated: challenge`, or 403/503 from a `server: cloudflare` origin) is terminal and surfaces as the new `blocked` error code with the action to take; any other 4xx stays terminal. Both the timeout and the retry budget are operator settings on the row (`installTimeoutSec` 30-600 default 120, `installRetries` 0-4 default 2), resolved per request so a settings save reaches the next install. The browser half renders the blocked class as its own localized sentence instead of the raw 403.
3. `packages/dsh-usage/src/core/spend.ts` owns the display decision: `resolveSpendDisplay()` normalizes the row's `spendCurrency` (`CNY`/`USD`, default `CNY`) and `cnyPerUsd` (default 7.2), and `formatSpend()` renders one stored CNY cost in that currency, answering a zero amount rather than `NaN` for an unusable input. The host stamps the resolved display on the overview document (`display`), and the foot card, the usage tab and the Token bank all read it. The ledger keeps storing CNY: switching the display never migrates history, and no live rate is fetched, so there is no fetch that could blank the card.
4. `shared/host/pair-access.ts` answers "not paired" when the service cannot be read (see the fence note); the three generated copies and the pet satellite carry the same guard.

## Alternatives considered

- **#1940**: keeping the row and widening the SDK dependency to a version that still exports `list-agents`. Rejected: the subpath is gone by design in the target cohort, and pinning an older cohort would undo the operator's upgrade.
- **#1941**: raising the timeout alone. Rejected: a slow origin and a transient 503 need different answers, and the issue's real complaint was that both ended in an opaque status code. Downloading through the browser half and handing files back over loopback was rejected as a new host/browser protocol, out of scope for this fix; Range-resume was left out because the installer already streams into a temp directory and one retry clears the realistic failure.
- **#1937**: fetching a live exchange rate from the host. Rejected: the plugin's host routes are loopback-fenced and the browser half has no network, so a fetch would add a failure mode the issue explicitly asked not to have; an operator-set rate is deterministic and testable.
- **#1942**: declaring `remoteWebUiPairing` in every consumer's `inject`. Rejected: it would make every plugin hard-depend on remote-web-ui, which the fence exists to avoid.

## Consequences

A liangshen preset mounts again on rc.3 and the comment keeps the row from being re-added. An install on a slow or flaky link has three attempts per request before failing, and a proxy that intercepts the market origin produces a sentence the user can act on. Spend can be read in USD without touching a single stored record. The fence no longer turns a missing optional service into an HTTP 400.
