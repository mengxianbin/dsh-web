# Agent Note: Open Issues Resolution (#1724, #1730, #1732, #1740, #1742)

Status: implemented

## Problem

Five open issues were actionable after #1728/#1741 were already fixed in 0.4.3, and two of them came from the family's own maintainers plus a transferred upstream report:

1. **#1740** — "Skins subscribed in the Workshop never appear in Settings - Skins": `bootSkinRuntime` registered its `dsh-skin-applied` window listener through the same `Set` that `emit()` iterated as SUBSCRIBERS, so the store's first `emit()` (the initial catalog load) ran the listener's own remover and unsubscribed it for the rest of the page. The `dsh-market` workshop card installs a skin and then announces it through that event, so an install could never converge on the open page unless the user reloaded. The same boot assumed the persisted selection only ever changes for the next page load, which stopped being true once the skin center's own preference row became an official settings row: the form writes it, the Host applies it, and nothing tells the running page.

2. **#1730** — "Second-instance ledger-lock conflict surfaces as not-mounted, and the restart advice does not hold": a row that throws during `apply` was never recorded as degraded, so `/api/dsh-web-all/degraded` answered `{"ok":true,"degraded":[]}` while `/rows` still listed the plugin. The task board could only see an unregistered route family (plain-text 404 from the Host webserver) and translated it into `board.hostError.notMounted` with advice to restart the DSH service, which cannot work while another process holds `$DSH_HOME/task-board/ledger-v2.lock`.

3. **#1732** — transferred `dsh-deep-whale#157`: the ORCA LINK character stage advertised a "new session" area much larger than the native button's hit box, only its decorated rows were pushed below the stage (the official Plugins row carries no third-party glyph, so it stayed inside), and a glyph mounted after the semantic adapter's first pass never re-marked its parent row.

4. **#1742** — transferred `dsh-deep-whale#159`: maid-atelier's body-level top trim (a 76px absolutely positioned band) painted over the official plugin manager page head, hiding the breadcrumb back to the plugin list.

5. **#1724** — the composer sent the whole conversation into a periodic jump while any skin-center visual was active. The official tooltip is rendered inside the composer card and is `position: fixed`; the neutralizer's rule put a `backdrop-filter` on `[data-composer-card]`, and a non-none `backdrop-filter` makes that element the CONTAINING BLOCK for its fixed descendants. The bubble then resolved its viewport coordinates against the card, landed far outside it but still inside the conversation scrollport, added ~1075px to `scrollHeight`, and every hover clamped the scroll to the new bottom (composer top 1164 -> 89) until the tooltip unmounted and the content snapped back — 82 jumps in 60 seconds.

## Decision

1. **The runtime store owns the applied-skin contract (#1740).** `SkinRuntimeStore` now carries its own seats (`doc`, `window`, `apiBase`, `fetchImpl`) so no runtime path reaches into the ambient globals, and `bootSkinRuntime` registers `trackSkinAppliedEvents` from its own teardown set (`listeners` and `teardowns` are separate sets; merging them was the defect). `watchPersistedSelection` polls `/api/skin-center/v2/active` on a 2s cadence while the document is visible, seeds its baseline from the current selection so boot is not repeated, ignores a value it already applied, and never writes the selection back. The client activation installs it through `ctx.effect`, so clearing the plugin row takes the listener and the timer with it. A skin announced before the page read the catalog triggers one `refreshCatalog()` first.
2. **A row that throws during apply is a recorded degraded row, and the board says why (#1730).** `packages/dsh-web-all` records the failure reason and exposes it, so the family state route answers with the cause instead of an empty list; `packages/dsh-task-board` reads that detail to distinguish "the routes are absent" (404) from "another process owns the ledger", and reports the owning pid with advice that can actually work. The ledger keeps its one-owner-per-ledger contract: the lock is not weakened and no cross-process write is added.
3. **The decoration yields to the page it covers (#1742).** maid-atelier's top trim keeps its band over the conversation and is hidden while the official plugin manager page occupies the main outlet, anchored on the official `data-plugin-panel` / `data-plugin-detail` attributes rather than any hashed class. Raising the page instead would hide the skin's own chrome, so the decoration is what yields.
4. **The ORCA stage positions the native panel list, not individual rows (#1732).** The whole `nav` list is placed below the stage so the official Plugins row and every third-party row move together, the new-session decor gains a hit surface while the navigation stays clickable, and the semantic adapter re-anchors a row when its relevant descendant or attribute arrives late instead of only on a full pass.
5. **The composer frost must not create a containing block (#1724).** The frost is painted by a body-level follower element (`data-dsh-composer-frost`) sized to the composer card, and no rule may put `backdrop-filter` / `transform` / `filter` / `contain` / `perspective` back on `[data-composer-card]`; the `--dsh-input-card-blur` setting keeps driving the same visual strength. The mechanism, its alternatives and its gaps are owned by the dsh-skins note [the composer frost rides a follower](https://github.com/zhu1090093659/dsh-skins/blob/main/.agents/notes/implemented/bug-fix/2026-09-27-composer-frost-follower-and-realm-safe-element-tests.md) - this batch only records that #1724 shipped it.

## Consequences

- Installing a skin in the Workshop applies it on the page the user is looking at, and a selection changed anywhere converges without a reload.
- A second DSH instance reports which process owns the task-board ledger and what to do about it, instead of suggesting a restart that cannot help.
- Skins no longer hide the official plugin manager's back entry, the ORCA character stage no longer swallows or misplaces its navigation, and no skin-center visual can make the conversation jump.
