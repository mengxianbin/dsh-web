# Agent Note: 看板隐藏官方「自动化任务」入口

Status: implemented

## Problem

DSH web shell 会在同一个侧栏里挂上两个调度面。官方 `ui-schedule` 浏览器半区贡献「自动化任务」一行，落在 Host Schedule 服务上——那是模型用 `schedule_create` 写下、由 Host 投递回会话的提醒；本仓的任务看板贡献「任务看板」一行，落在自己的 Host 账本上，按 cron 计划启动真实 DSH 会话。装上家族的部署因此把两行并排放在侧栏里，而两者做的事并不相同：官方那面是提醒目录，看板这面是带权限门、run group 与子任务级联的任务账本。看板是家族里更完整的那一面，侧栏却为同一件事给出了两个入口。

两面都不能从 Host 侧摘掉。本仓不改 DSH 源码 checkout，而官方 Schedule 服务是 Host 自己的：模型通过 `schedule_create` 写下的提醒存在那里，仍然需要自己的页面。看板的总开关已经掌握着看板自己那一行（关掉看板就同时藏起该行与看板视图），因此侧栏里这个重复入口必须跟随同一个开关，而不是无条件消失。

## Decision

看板启用期间，看板的浏览器半区隐藏 shell 官方的「自动化任务」行；关掉看板，这一行随之回来。

守卫位于 `packages/dsh-task-board/src/client/suppress-schedule-row.ts`。它从 shell 自己的面板列表账本里读官方条目（id `schedules`），并用 shell 面板投影同款 `resolveSlotLabel` 调用取出该条目的可访问名，于是匹配跟随当前语言，而不是写死一条译名。随后它在 shell 的全局面板列表座位（`sidebar.panellist`，槽位渲染器为每一行打的锚点）里定位该行，只在 shell 自己的按钮上写一次行内 `display: none`。该行仍然挂载，React 继续拥有它；官方页面在其他仍可触达的地方照常工作；每次 DOM 变化后这次写入都会通过家族共享的 body 变更枢纽重新补上，因为 shell 随时可能挂载或替换这一行。

该状态由看板的总开关掌握，与看板自己那一行完全同源：守卫在挂载看板行的同一个分支里隐藏官方行，在卸载它的分支里恢复官方行。没有官方插件的部署，其账本里根本没有这条目，守卫因此什么都不藏。

## Alternatives considered

- **在 profile 里停用官方 `ui-schedule` 装载行。** 行级 `disabled` 覆盖是官方支持的「让某个插件不进 profile」的做法，也是第一候选。它输在三处：覆盖是静态的，于是家族聚合包的补丁层会在看板已关闭的部署里同样藏起官方行；它连官方页面一起去掉，于是 `schedule_create` 写下的 Host 提醒被搁置；而覆盖一个 profile 根本没声明的行是一条陈旧条目，loader 还得去清理它，家族装在没有 `dsh-web-app` 的 profile 里就会带着死配置。

- **在槽位账本里遮蔽官方行。** 列表单元的胜出者是优先级最低的那一条，所以用官方 id 注册看板的行确实能顶掉官方行——但前提是看板还要用同一个 key 遮蔽官方的 `main` 页面，那等于让看板变成官方面板（宿主自己的面板埋点会把看板记成 cron 面板），代价是看板丢掉自己的面板身份。看板保留自己的 id，官方行是被藏起来而不是被顶替。

- **用 CSS 按官方时钟图标或写死的译名隐藏。** 官方行不带插件自有钩子（家族自己的行带，皮肤正是靠它解析行属于哪个插件），时钟图标与其他界面共用，写死的译名则只在一种语言下成立。账本给出的是 shell 自己渲染的那条标签，守卫从那里读。

- **让 Host 自己拥有这个选择（在槽位契约里加一个「被取代的面板」概念）。** Host 的槽位契约没有这个概念，而本仓不能改 Host checkout，因此这个问题留给上游；守卫是在现有契约下能落地的最小做法。

## Consequences

看板开启时侧栏只有一个调度入口，关掉看板官方入口随之回来。官方「自动化任务」页面没有被移除：模型写下的 Host 提醒仍然可达，家族的选择不会搁置任何东西。

守卫读的是 shell 的行标记——槽位锚点与可访问名。若 shell 不再打这些标记，官方行会重新可见；那是多出一个可见的重复入口，而不是看板坏掉，而看板自身从不依赖这个守卫。

## Testing

`packages/dsh-task-board/tests/suppress-schedule-row.spec.ts` 钉住这份契约：看板开启时官方行被隐藏、其它行不受影响、看板自己那一行永不被隐藏、看板关闭时官方行回来、没有官方插件的部署什么都不藏、壳替换掉那一行后它再次被隐藏。真实 Web GUI 是另一半证据：看板启用时侧栏只有一个调度入口。
