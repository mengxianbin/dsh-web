# Agent Note：任务表单按折叠区域分组

Status: implemented

## 问题

所有任务对话框（新建、复制、编辑、子任务）都把字段堆在一列里：标题、描述与执行 Prompt、标签、冻结块、交接包引用、工作区 / Agent 预设 / 权限 / 模型钉住、会话复用、/goal 与 cron 定时。在 `max-height: calc(100vh - 96px); overflow-y: auto` 的 520px 对话框里，表单必然出现滚动条，而多数卡片根本不会改的执行设置把 Prompt 和底部按钮挤出了视野。

同一个字段的名字也不准确：Agent 预设钉住被标成「模式」，看不出它选的是什么；而运行时名单里四个内置预设行本身没有展示名，选择器只能把裸 id（`standard`、`ptc`、`minimal`、`cordis`）和用户预设并排列出。

## 决策

任务表单改为若干可折叠区域。

### 外壳

- `ModalShell` 把字段放进 `.modalBody`，这是对话框唯一的滚动容器（`overflow-y: auto; min-height: 0`）；`.modal` 保留 `max-height` 但改为 `overflow: hidden`，标题与底部操作栏因此固定。滚动条只在视口极矮或用户把所有区域都展开时作为兜底出现，默认布局不需要它。
- 正文的每个直接子元素都是 `flex: none`。列方向 flex 子项默认会收缩，被压缩的区域会把自身字段藏在 `overflow: hidden` 之后而不是让正文滚动——这个缺陷只有真实浏览器的渲染测量能抓到（jsdom 没有布局）。
- `CollapsibleSection`（`client/board/TaskForm.tsx`）渲染一个带 `aria-expanded`、`data-dsh-part="form-section"` 与边框绘制折角的标题按钮（不用字形，字体与 emoji 都无法改变它），区域正文只在展开时进入 DOM。`forceOpen` 让拥有者在区域内有阻塞错误时强制展开，校验失败不会被藏在折叠区里。
- 外壳按矮窗口调过：外壳间距 10px、正文间距 8px、标题内边距 7px，描述字段默认两行。

### 区域

`NewTaskModal` 渲染：AI 解析（仅当部署提供解析面）、任务内容（**默认展开**，并承载副本的「创建后归档原任务」）、标签、执行设置、运行方式、交接与续跑、定时运行。每个折叠标题都带一行当前值摘要，用与字段相同的本地化文案拼出（通用情形用 `new.summary.*`），折叠不会无痕地藏掉配置。带阻塞错误的区域——cron 无效、冻结块格式错误、解析失败——会被强制展开。

### Agent 预设

- 字段在新建对话框与任务详情统一改名为「Agent 预设」（`new.agentPreset` 取代 `new.mode`），因为两处提供的是同一个选择。
- 选择器仍以运行时名单为唯一权威，并分组呈现：四个内置预设排在 `exec.mode.builtinGroup` 下，其余行排在 `exec.mode.customGroup` 下。内置行在名单里没有展示名，因此 `client/board/preset-label.ts` 只为这四个 id（`standard` / `ptc` / `minimal` / `cordis`）提供本地化名称。该映射只是展示层糖：不认识的 id 依次回退到名单名与 id，既不会隐藏也不会改名任何预设。
- 空值即「继承」选项。`inheritPresetLabel` 会写出这次运行真正落到的预设——名单中 `isDefault` 的那一行——所以「继承（部署默认：标准）」直接说明了未钉住时会用哪个。
- 任务详情的执行设置复用同一组助手；交接包摘要改用继承文案，不再使用已删除的 `exec.mode.default`。

### 文案

zh 与 en 字典在包内，ru 由 `packages/dsh-i18n` 镜像。`new.mode` 与 `exec.mode.default` 是替换而非保留别名；`exec.hint` 现在说明 Agent 预设决定会话组合。

## 备选方案

**保持单列、把它压小（减少 textarea 行数、缩小字号）。** 否决：520px 对话框在任何可读字号下都放不下这些配置，而用像素预算隐藏等于无声隐藏——折叠至少给出当前值摘要。

**展开一个区域就自动收起兄弟区域的手风琴。** 否决：一边看定时一边对照工作区钉住是常见的编辑动作；让区域各自独立，表单不去猜意图。全部展开时由正文的滚动兜底。

**标签页（内容 / 执行 / 定时）。** 否决：任务对话框里的标签页是陌生布局，等于用第二套导航再藏一次同样的配置；用户要求的是折叠/展开。

**把四个内置预设写死成选择器的全部内容。** 否决：运行时名单才是权威且已包含用户预设，只列内置会让用户预设无法钉住。

**在看板级配置一个默认预设。** 否决：部署默认已经是继承目标，再加一层看板钉住会静默覆盖它；判断发生在每张卡片上，选择就留在卡片上。[新建卡片默认值](./2026-10-14-task-board-new-card-defaults.zh.md) 决策后来以**预填**形态采纳了看板级默认值——对话框预选的值，加一个「不设置即不改变任何行为」的空值——因此这条否决（针对的是钉住）不适用于该形态。

**只在新建对话框改名。** 否决：新建对话框与详情页钉的是同一样东西，一个选择两个名字正是这次要消除的困惑。

## 后果

- 对话框打开时约六行；执行设置一次点击可达，折叠摘要仍显示其当前值。
- 四个内置预设显示为名称而非 id，用户预设照名单原样列出。展示映射绑定随包发布的内置 id：改名后的部署仍显示名单名或裸 id（不会出错，也不会让测试变红）。
- 详情页的预设字段与交接摘要随新建对话框一起改文案；不涉及任何持久化值、线协议字段或账本 schema。
- 覆盖：`tests/create-dialog-sections.spec.tsx` 覆盖默认展开/折叠布局、展开区域、折叠摘要、内置/自定义分组与继承默认、以及错误强制展开路径；`tests/responsive-css.spec.ts` 守住外壳的溢出契约与边框折角；既有对话框用例经 `tests/form-sections.ts` 先展开区域再驱动字段。
- 单元用例之外的证据：一个临时脚手架（忽略提交，位于 `test-results/form-qa/`）在无头 Chromium 里渲染真实组件与样式表并测量外壳。1440x900 与 1180x720 下默认布局需要 533px 正文高度、可用也是 533px——没有滚动条也没有被裁掉的字段——只有用户展开某个区域后正文才滚动。
- 本进程无法驱动真实 DSH Web GUI（拿不到宿主按进程生成的 token），因此聚合挂载 lane 仍是仓内的 GUI 检查，重建产物后仍欠一次真实 GUI 内的视觉走查。

这些界面的字号尺度、结果槽位与折叠行为由[卡片界面呈现契约](2026-10-20-task-board-card-surface-contract.md)所有。
