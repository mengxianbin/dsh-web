# Agent Note: 任务看板的新建卡片默认值

Status: implemented

## Problem

新建一张卡片意味着再把同样的四个执行目标选一遍。把每张卡片都跑在同一个 agent 预设、权限、模型与思考档位下的部署，要在新建对话框里重复选同样四个值；从对话里建卡的模型则要在每次 `task_board_create` 调用上把它们传一遍。看板设置没有任何地方说明一张**新**卡片从哪开始：现有设置讲的是看板的运行行为与 goal 验收，而创建路径存的就是调用方传进来的值，因此省略一个执行目标始终意味着「不钉住，运行时解析」。

把省略直接解释成「套用默认值」会一次改变所有地方的这层含义：GUI 表单、看板自己的 agent 工具与扩展提供方的 `tasks.create` 写的是同一条创建路径，旧浏览器数据的一次性导入动作则单独归一化已存的行。

## Decision

设置卡增加一个专题「新建卡片默认值」，承载四个 volatile 键：`cardDefaultMode`、`cardDefaultPermission`、`cardDefaultModel`、`cardDefaultReasoningEffort`。四个键的默认值都是空字符串，不钉住任何值：完全不配置它们的部署创建卡片的行为与这个专题出现之前完全一致，改动后的值作用于之后新建的卡片，无需重启。该专题是设置卡主题清单里再追加的一行折叠卡（[设置折叠主题卡](./2026-10-01-task-board-settings-disclosure-cards.zh.md)），由那张卡唯一的保存写入。

四个值都是预填，绝不是钉住。GUI 新建对话框打开时已选中配置的值，用户可随时改；卡片存下的是创建时确定的值，之后仍可编辑，与其它执行目标一样。

一张新卡片的每个目标按同一顺序取值：对话框里的显式选择优先于从建卡来源带过来的值，后者优先于看板默认值。复制卡片保留源卡已钉住的全部值，只为源卡没钉住的字段补默认值；从父卡新建的子任务同样沿用父卡已钉住的值，唯一例外是父卡的**权限**永不参与——权限不在创建时复制到卡片上（该不变量归[子任务决策](./2026-09-24-task-board-subtasks.zh.md)所有），它在启动时按祖先链解析，连同提供该绑定的祖先的人工确认戳一起生效。

`cardDefaultReasoningEffort` 与 `cardDefaultModel` 的绑定关系，和卡片自己的档位与自己模型的绑定完全相同（[思考强度决策](./2026-10-11-task-board-reasoning-effort.zh.md)）：默认档位只在卡片最终钉住的模型就是配置的默认模型时才生效。自己选了模型的调用方不借用任何档位——既不是源卡的，也不是默认的；`cardDefaultModel` 留空则默认档位失效。

默认权限可以高于会话权限基线。这是一个配置选择，不是绕过：该值只是表单提供的预填，既有的事前确认门纹丝不动，因此有效权限高于基线的卡片仍要等人工确认该绑定后才能运行。

Host 创建路径按 opt-in 补齐。创建动作新增布尔标志 `applyCardDefaults`，开启时用看板默认值填上调用方没有给的目标，`task_board_create` 会设置该标志。不带这个标志时创建动作的行为与之前完全一致，因此扩展提供方的 `tasks.create` 与旧浏览器数据导入——两者都不设置它——对省略字段仍保留各自的含义。

保存后的默认值会到达已经打开的页面。看板客户端订阅的正是设置卡保存时写入的那份设置表单：四个 `cardDefault*` 键的签名发生变化时，它重新读一次权威的 Host 快照（`BoardController.refreshHostState()`），因此在同一个页面会话里稍后打开的新建对话框无需刷新即按刚保存的值预填；清空某个默认值同样立刻不再提供——Host 对「未配置」的表示是省略该键，所以浏览器镜像对该字段以快照为准，而不是沿用上一次的值。一次保存只触发一次重读，改无关设置不触发。

## Required verification

- 四个键持久化在设置命名空间中、均为 volatile，且留空时每条创建路径的行为与之前逐字节一致：既不新增钉住，也不替换默认值。
- GUI 对话框把每个已配置的默认值显示为选中值，并允许用户改写；创建出的卡片存的是改写后的值，而不是默认值。
- 每个创建方都满足优先级：对话框的显式选择优先；复制卡片保留源卡的钉住值、只对源卡未设置的字段套用默认值；从父卡新建的子任务只在父卡未钉住处解析默认值，且绝不取父卡的权限。
- 档位绑定在各方向都成立：只有卡片最终模型就是 `cardDefaultModel`、且调用方没有自己选模型时才套用默认档位；自己选了模型的调用方拿不到任何档位，既不是源卡的也不是默认的；`cardDefaultModel` 留空时默认档位失效；源卡自己的模型/档位组合仍成对传递。
- 确认门照旧成立：默认权限高于基线时卡片仍处于未确认状态，人工确认前手动执行与 cron 触发仍被拒绝。
- `applyCardDefaults: true` 只填调用方省略的值，绝不覆盖调用方传入的值；同一个创建动作不带该标志、提供方的 `tasks.create` 与旧数据导入产出的卡片不变。
- 保存默认值会到达已经打开的页面：不刷新页面的情况下，保存后打开的新建对话框按新值预填；清空某个默认值后，下一次打开该字段回到未设置。

## Alternatives considered

**只在浏览器侧预填。** 否决：这样通过看板 agent 工具创建的卡片会无视已配置的默认值，同一块看板会因为创建者不同而给出不同结果；用一条设置覆盖两条创建路径正是这次改动的目的。

**把省略的执行目标读成「套用看板默认值」。** 否决：缺席本身就是一种值——「不钉住、继承」就是这样存的——重新解释它会给从未配置过默认值的部署悄悄钉住卡片，而且会波及共享同一创建动作的扩展提供方 `tasks.create` 与旧数据导入。opt-in 标志把这个新行为限制在主动索取它的路径内。

**用一份通用档位列表作为默认档位的候选项。** 否决：模型支持的档位归适配器所有，既有档位决策也已经否决过统一的 low/medium/high 列表；一个目标模型未声明的默认档位最终只能在运行时被选模拒绝。默认档位与卡片自己的选择器取自同一份由目录推导的列表。

**做成看板级钉住，而不是预填**——也就是[新建对话框决策](./2026-09-27-task-board-create-dialog-regions.zh.md)在部署默认值还是唯一继承目标时所否决的那种形态。这里同样否决：钉住会覆盖用户从未配置过的每一张卡片上的部署默认值。带自己「未设置」状态的预填则把那个继承目标留在原处，因此那份记录所保护的东西依然成立——每张卡片的选择仍留在做判断的地方。

**用看板事件流的帧发布默认值。** 试过、在隔离探针上实测过，并已回退。该方案会让浏览器镜像改为跟 SSE 帧，并在 volatile 配置写入后补发一帧。连接帧携带的确实是当前值，但一次保存后补发的那一帧携带的是**提交前**的旧值——连续两次编辑都是慢一拍——而同刻 `GET /api/task-board/state` 已经是新值：Loader 把 volatile 更新交给它的 fiber 时，新文档对该 fiber 尚不可见。帧还以「无条件覆盖」合并进镜像，那个旧值因此可能盖掉更新鲜的值，比它想修的缺陷更糟。改为按设置表单的签名重读快照后，这两个问题都不存在。

## Consequences

- 想让卡片统一用一个 agent 预设、权限、模型与思考档位的部署只需配置一次；任何卡片仍可不同，未配置默认值的部署对所有人保持今天的行为。
- 默认值抬不动权限确认门：它们改变的是新建表单提供什么，而不是 Host 允许什么运行。
- GUI 对话框与带 `applyCardDefaults: true` 的 `task_board_create` 从此对「未设置的目标落在哪里」给出一致答案；扩展提供方自己的创建路径与旧浏览器数据导入保持不变，对省略字段仍保留各自的含义。
- 设置卡在自己专属的专题里多出四个键，点名它们的那一行折叠卡承载整个特性；从不打开它的部署不受影响。
