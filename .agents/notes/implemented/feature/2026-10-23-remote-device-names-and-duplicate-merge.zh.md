# Agent Note: 已授权设备支持命名，并可显式合并重复记录

Status: implemented

## Problem

桌面远程面板每次渲染都从已存 User-Agent 实时推导设备名（`deviceNameFromUserAgent()`），因此一台手机显示为 `Android · Chrome`，同一台手机再次扫码就生成一条名称完全相同、会话 id 不同的记录。配对有意在每次 accept 时铸造新会话，因为移动端 cookie 上下文会分裂（相机预览、内嵌浏览器、系统浏览器）；而 `maxDevices`（默认 4）是硬上限，重复记录会静默挤掉更早的授权。设备列表既没有命名手段，也没有合并手段。浏览器配对路径本身归[远程界面复用笔记](../architecture/2026-08-29-remote-control-reuses-official-ui.md)所有；本笔记负责设备列表的命名与重复处理。

## Decision

`DeviceSession`、`DeviceSnapshot` 与客户端 `DeviceFrame` 增加可选 `name`，写入既有 `devicesFile` 设备库；面板用 `deviceDisplayName()` 渲染：自定义名优先，其次 UA 派生名，最后是本地化的「未知设备」回退。名字只是展示元数据，永不进入授权判定；设备 id 仍是唯一凭据。

重命名是 `POST /api/pair/rename`（`{deviceId, name}`），与撤销同在本机回环控制面；空白名清除标签。重复记录的处理保持显式：配对仍在每次 accept 时铸造新会话，因为两台物理上不同的设备可以上报同一 User-Agent。分组只是展示层行为（`duplicateDeviceGroups()` 按精确非空 User-Agent 分组），给出「可能是同一台设备」提示与合并按钮。`POST /api/pair/merge`（`{deviceIds}`）保留最近活动的一条、撤销其余，拒绝跨 User-Agent 与未知 id，在存活记录没有名字时继承被合并记录上已输入的名字，并沿既有撤销落盘路径持久化。

触发按钮同时加上 `data-testid="remote-trigger"`，外部插件不必再依赖面板根与触发按钮共用的 `aria-label`。

## Alternatives considered

- **在 accept 时按 User-Agent 自动合并。** 否决：相同 UA 不能证明是同一台物理设备。静默撤销两台同型号手机中的一台，等于替操作者撤销了一条他从未撤销的凭据——这正是逐设备控制要避免的无声损失。
- **把名字放到另一个插件拥有的旁挂文件。** 否决：浏览器路径已经拥有设备库，第二个文件会与它所命名的会话漂移（会话被撤销后仍留下过期标签）。名字属于会话行，并随会话消失。
- **在面板里用 N 次 revoke 调用实现合并。** 否决：存活行必须基于操作者看到的同一份快照挑选，而 N 次独立调用在失败时会让面板留下半组合并状态。一次宿主侧操作选定存活行，并且只写一次撤销。

## Consequences

- 设备名跨重启、跨 sweep 保留；设备库多出一个可选 `name` 键，旧文件只是没有它。
- 合并就是撤销：被合并记录的浏览器在下一次请求时被切断，与取消配对完全相同。「可能是同一台设备」的措辞正说明这需要操作者判断。
- 两个新端点都在回环栅栏之后，不增加局域网或隧道面；README 安全模型把它们与铸造/停止/撤销并列。
- 测试固定了服务语义（清洗、空白清除、合并存活/拒绝/名字继承、持久化）、路由栅栏与载荷契约，以及面板流程（内联重命名、重复提示与合并）。
