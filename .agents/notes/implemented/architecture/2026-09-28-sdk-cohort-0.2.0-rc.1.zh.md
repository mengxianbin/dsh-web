# Agent Note: SDK cohort 0.2.0-rc.1

Status: implemented

## Problem

集成分支声明的是 `0.1.7-rc.2`，而官方家族已在 2026-09-28 发布 `0.2.0-rc.1`（npm `next`，宿主 CLI 于 12:34Z 发布），且这不是同一线上的版本推进：它开启了 `0.2.0` 系列，并带来发布说明中归入「体验优化」「问题修复」「其他变更」的内容。按兵不动会让家族的可读下限指向一个已被跨越的宿主，也会让家族停留在 rc 线，而官方 shell 已转向 0.2 组合。

两个事实塑造了本次迁移。其一，运行中的宿主远高于声明下限：正在运行的 DeepSeek Harness 桌面客户端、Homebrew 的 `dsh` CLI 以及所有本地 profile 都停在 `0.1.7-rc.2`，因此本次变更前后插件 SDK 与其宿主运行时始终处于同一条发布线。其二，渲染后的回答补丁不是钩子的输入：0.2 的 shell 通过 character-data 变更流式写入回答文本，而聚合包的 body-mutation hub 为每一个 token 付出了整帧重扫的代价，其钩子却都不读取这个被改动的子树。

## Decision

整个 cohort 一次性迁到 `0.2.0-rc.1`，在隔离工作树 `feat/dsh-0.2.0-rc.1-upgrade`（`/Users/zcl/code/.worktrees/dsh-web/feat-dsh-0.2.0-rc.1-upgrade`）中进行，该工作树由 `wt switch --create` 从本地 `dev` 顶端（`331b1118`，领先 `origin/dev` 一个未推送提交）创建，因此在整合之前共享 checkout 与运行中的 GUI 不受影响。它承接 [sdk-cohort-0.1.7-rc.2](2026-09-24-sdk-cohort-0.1.7-rc.2.md)：其记录继续拥有 rc.2 迁移，本记录拥有 0.2.0-rc.1 迁移，不取代前者。

### 一个 cohort，一个字面量

53 个文件中共 354 处，另有 `pnpm-lock.yaml`：十六个家族清单、插件脚手架、shared 工作区包、`dsh.engines.dsh` 下限及其逐字相同的 `@deepseek-ai/dsh` 宿主 peer、根清单自身的 SDK devDependencies、发布冷却排除账本（68 条）与两个按新 cohort 重新键入的 `packageExtensions`、根 README 双语徽章、CI 与发布挂载冒烟 pin、`shared/web-platform.ts`、`shared/tests/web-platform.spec.ts`、`tests/e2e/mount.e2e.ts`、`scripts/rollout-verify.test.mjs` 与 `scripts/aggregate.test.mjs` 中的 cohort 字面量，以及 `docs/publish-prep.md`、`docs/plugins.md`、`packages/dsh-web-all/aggregate.yml` 与七个包 README 配对（其配对记录已重新登记）中的 cohort 表述。`@deepseek-ai/cordis`（4.0.4）与 `@deepseek-ai/schemastery`（3.18.4）不移动：二者都没有发布 `0.2.0-rc.1`，它们的线是独立的，且 cohort 自身的 peer 仍在指定它们。

### 已发布产物层面的差异

两个 cohort 的 tarball 都被解包比对，而不是依据发布说明推断。在 43 个被消费的包中：零个被移除的导出、零个重命名、恰好两个新增导出（`@deepseek-ai/dsh-session` 的 `ToolCallRecovery`、`@deepseek-ai/dsh-client-ui-conversation` 的 `reportMessageSubmission`），`exports` 映射、`main`/`types` 入口、engines 与 `dsh` 元数据逐字节相同，前端 `staticModules` 表也逐字节相同（`react`、`react/jsx-runtime`、`react-dom`、`react-dom/client`、`@deepseek-ai/cordis`、`@deepseek-ai/dsh-client-store`、`@deepseek-ai/dsh-client-ui-slots`、`@deepseek-ai/dsh-client-ui-primitives`、`@deepseek-ai/dsh-client-ui-dockkit`）——因此 `shared/web-platform.ts` 保留其清单，只移动来源注释。

确实存在的类型面差异全部是增量的，且都不触及本仓消费者：`dsh-plugin-manager` 注入的官方 Plugins 页槽位契约（`plugins.detail.section`）在两个 cohort 上逐字节相同；对话包在其既有 composer 契约旁新增了一个 submission-analytics 模块；primitives 包没有新增家族导入的内容。`@deepseek-ai/dsh-api-remotes` 在其生成的模块图元数据里多出一行仅类型再导出（`@deepseek-ai/dsh-client-product-analytics/remote`）——与 rc.2 上那 34 行指向本仓从不安装的包的写法完全同形，且只经一个没有任何 `exports` 子路径暴露的包内文件 `lib/types/client/index.js` 抵达，这正是该包缺席时本仓 `skipLibCheck` 类型检查依然通过的原因。没有修补任何已安装文件。

### 一项被回退的体验改进采纳

0.2 的 shell 以流式方式写入回答文本，React 以 character-data 变更记录提交它。聚合包的页面级 body-mutation hub 会把这类记录投递给 shim 以及每一个靠 DOM 挂载的家族插件，随后各自重扫整帧——按 token 计，而其中没有一个读取那个子树。

我们在 `shared/client/body-mutations.ts` 中实现了页面级批次过滤器（跨 bundle 的 `Symbol.for` 槽位，替换而非叠加，遇到未知记录一律放行），并在聚合 shim 中加入 `isUnobservableAnswerPatch` 判定，两层都有测试。随后在提交前回退，因为其正确性建立在一个 shell 并不保证的假设上：判定器依靠容器属性、以及记录的 `target` 是新增节点的祖先来识别回答内容；这对常见流式路径成立，但对「React 提交重建回答容器父节点」的情形不成立——这是一个测试无法观察的分支，而误判一个批次不只是浪费一帧，它会让已打标的钩子变陈旧。可量化的收益也有限（每次流式提交省一次帧扫描，而每帧调度本身已在所有订阅者之间共享），因此不值得用一个未经证实的判定去承担该失效模式。完整推理、被否决的形态与重新引入条件记录在本记录中：hub 不保留过滤器，未来若再尝试，应先针对真实流式会话而非 fixture 证明记录形状假设。

## Alternatives considered

**只升级宿主、SDK 包留在 rc.2。** 否决：家族的下限、peer、徽章与挂载 pin 是同一份契约，把它们拆到两条发布线正是 [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) 要防止的状态。

**等 `0.2.0` 稳定后再动，家族继续留在 rc 线。** 按操作方要求否决：0.2.0 候选版承载的正是本次变更要采纳的改进，而家族适配的线就是已发布宿主所在的那条线。

**保留 body-mutation 过滤器。** 依证据否决：判定器的正确性依赖一个只有真实流式会话才能确认的 DOM 形状假设，而其失效模式会静默地让页面上每个 DOM 钩子退化。有限的帧扫描收益不足以支撑一个未经证实的判定器。

**让任务看板采用官方 schedule bundle 作为计时引擎。** 本次 cohort 否决：该包默认关闭，采纳它要么交付一个默认关闭的功能，要么替官方刻意留给用户的产品决策做决定。任务账本自身的调度器仍是权威；迁移属于待办工作，不是 cohort 义务。

**新增 `@deepseek-ai/dsh-client-product-analytics` 根依赖以满足新的仅类型引用。** 否决：该引用位于没有任何 `exports` 子路径暴露的包内模块图文件中，且 rc.2 上已有 34 行同形引用指向本仓从不安装的包。新增依赖等于把上游打包产物制度化成本仓要求。

## Consequences

- 声明下限、宿主 peer、徽章、CI/release 挂载 pin 以及无桌面端的 host floor 集合都指向 `0.2.0-rc.1`，锁文件把每个 `@deepseek-ai/dsh-*` 键解析到该版本。
- 运行中的桌面客户端与本地 `desktop` profile 仍持有 `0.1.7-rc.2` 影子副本。它们会在宿主 CLI 迁移、profile 刷新后收敛；在那之前 profile 树继续在自己的 cohort 上工作，且不对运行中的实例做任何 profile 手术。
- 卫星包（`@linxin666/dsh-pet`、`dsh-client-ui-skin-center`、`dsh-client-ui-community-plugins`、`dsh-client-ui-preset-center`）自身声明 `>=0.1.7-rc.1` 下限。它们接受新宿主（`>=` 下限可被更高的宿主满足），并由各自仓库迁移到对齐版本。
- 该基线上没有 `desktop/` 目录树，因此 [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) 点名的第六个 host floor 面——桌面打包运行时 pin——没有可移动的对象。本次变更不产生待办的桌面重发布。

`bash scripts/e2e-mount.sh` 以其 CI 形态对从 registry 安装的临时 `@deepseek-ai/dsh@0.2.0-rc.1` 宿主运行（`DSH_CMD` 指向该安装，`FAMILY_TGZS_DIR` 指向本检出打包的 tarball）：聚合包经 `dsh plugin --profile web add` 挂载，`dsh web` 在 OS 分配的带令牌 URL 上启动，Playwright 无头 lane 通过——官方宿主帧挂载，且被排除的外部行不出现。
