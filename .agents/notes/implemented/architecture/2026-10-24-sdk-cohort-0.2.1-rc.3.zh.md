# Agent Note: SDK cohort 0.2.1-rc.3

Status: implemented

本记录拥有 0.2.1-rc.3 迁移。[SDK cohort 0.2.1-rc.2](2026-10-17-sdk-cohort-0.2.1-rc.2.md) 保留此前迁移及其被否决的方案。

## Problem

主仓与四个卫星仓都声明 0.2.1-rc.2 cohort，而操作者的宿主运行 0.2.1-rc.3。新的官方版本增加区域级插件「更多」菜单、在「新会话」导航中保留未发送草稿，并改变 DeepSeek 模型列表。正确的适配必须覆盖主仓包、独立归属的卫星仓、生成的市场输入和官方加载器行命名空间，而不是只改一个依赖字面量。

## Decision

主工作区消费的 `@deepseek-ai/dsh-*` 区间推进到 `^0.2.1-rc.3`；每个家族清单和脚手架声明 `dsh.engines.dsh >=0.2.1-rc.3`，宿主 peer 与其一致。README 徽章、CI 与发布挂载 pin、工作区 package extensions、release-age 豁免和 lockfile 同步移动。Cordis 保持 `^4.0.5`，schemastery 保持 `^3.18.5`，它们仍是本 cohort 的版本。

官方证据是 [dsh-v0.2.1-rc.3](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.3) 与 [rc.2...rc.3 compare](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.2.1-rc.2...dsh-v0.2.1-rc.3)。npm 的 `next` 提供 rc.3，`latest` 仍是 rc.2；操作者安装的 rc.3 宿主是本次适配目标。插件管理器的下限会明确拒绝更老宿主，而不是声称未验证的兼容性。

契约审计得到以下边界明确的适配：

- 官方 `dsh-web-app` patch 新增 `entry-customization`，因此 `packages/dsh-plugin-manager/tests/bundle-row-id.spec.ts` 的快照收录该 id。既有插件页 DOM 席位没有变化。
- `DraftInitializationOptions.whenDraftExists` 是可选字段，`conversation.chat.turnTail` 仍存在，且没有家族包实现发生变化的 `MessageSubmissionState` 或会话头部 owner。消息编辑接线无需源码变更。
- shell 仍导出相同的 11 个冻结平台模块。皮肤中心重新扫描仍得到 329 个官方 token。共享来源注释随版本更新，但不加入臆测性的运行时或 DOM 补丁。

每个卫星仓各自拥有并验证自己的 cohort 变更：dsh-skins `d37711f`、dsh-pet `26136ed`、dsh-presets `88e508e` 经 [dsh-presets PR #3](https://github.com/zhu1090093659/dsh-presets/pull/3) 合并为 `f491e89`，以及 dsh-community-plugins `42cad66`。四个提交均可从各自远端 `main` 获取，主仓 gitlink 指向这些提交。包版本不变，也不向 npm 发布。

聚合包、共享副本、入库的 `lib/` 产物与指纹以及市场输入都经各自拥有者的工具重新生成。主仓改动保留在本地 `dev`；必须公开的卫星提交先进入各自远端，再移动 gitlink。

## Alternatives considered

**只推进主仓。** 否决：操作者明确要求包含卫星仓，而市场构建读取它们钉住的内容。它们的清单、契约与验证必须在各自仓库推进，不能在主树里直接改写不属于主仓的内容。

**因为 npm `latest` 尚未前进而停在 rc.2。** 否决：用户指定且本机安装的是 rc.3，rc.3 SDK 包已发布到 npm，兼容下限必须指向实际通过验证的 cohort。`next` 与 `latest` 的区别如实记录，不隐藏。

**修改链接的官方 DSH checkout 或绕过缺失 API。** 否决：官方 checkout 只作为只读比对证据。开发类型来自 npm 发布的 SDK 包，rc.3 类型检查没有发现需要绕过的家族 API 删除。

**把兼容更新变成一次发布。** 否决：没有发布请求。家族版本保持 0.4.8，不创建 tag，也不向 npm 发布。

## Consequences

- 主仓 lockfile 中剩余的四个 `>=0.2.1-rc.2` 宿主 peer 属于当前已发布的卫星 npm 制品，而不是更新后的卫星源码仓。在后续发布替代这些制品之前，它们仍然正确；gitlink 与市场输入指向新的源码提交。
- 插件管理器会对后续家族制品要求 rc.3。仍在 rc.2 的宿主（包括当前 npm `latest` 线）会得到确定性的兼容拒绝，而不是安装未经测试的包。
- rc.3 契约本身无需运行时 JavaScript 迁移：变更包括清单、兼容快照、测试、来源说明、生成产物和文档。验证过程中还发现并修复了一个既有的 Windows-only `DeviceRoster` 并发写盘竞争，单独记录在[串行化设备名册写盘](../bug-fix/2026-10-24-remote-bridge-roster-write-serialization.md)。历史发布说明、fork 来源与 `docs/archive/` 记录保持不变。
- 该 cohort 同时移除了 `@deepseek-ai/dsh-tool-subagent-control/list-agents` 子路径导出（该包现在只导出 `.`），而 liangshen 预设仍声明那一行，导致其会话无法挂载，直到该行被删除。这一适配与同日另外三处修复由 [issue 批次 1937-1942](../bug-fix/2026-10-24-issue-batch-1937-1942-fixes.md) 拥有。
- 本次工作从不重启或中断用户正在运行的 DSH 服务。验证使用隔离 home 与进程；现有服务要加载本地新构建，需要操作者自行重启。

- 主仓完整门禁通过：冻结安装、类型检查、全工作区测试、`test:scripts`（459 个测试）、`test:standards`、`docs:check`、`i18n:check`、`emoji:check`、`aggregate:check`、`runtime-deps:check`、`sync-shared:check` 与 `libs:check`。`market:fetch --check` 与 `market:check` 按新 gitlink 校验全部 5947 个生成文件。
