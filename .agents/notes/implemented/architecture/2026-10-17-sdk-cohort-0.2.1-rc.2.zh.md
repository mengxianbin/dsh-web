# Agent Note: SDK cohort 0.2.1-rc.2

Status: implemented

取代 [让每个包的 invariant 伴生模块与它实际发布的内容一致](../simplification/2026-10-10-invariant-companion-surface-honest.md) 的 runtime invariant 表面，并与 [移除 dsh-model-capabilities](../simplification/2026-10-17-model-capabilities-native-removal.md) 一起取代 [sdk-cohort-0.2.0-rc.2](2026-09-29-sdk-cohort-0.2.0-rc.2.md) 所记录的能力编辑器重叠行。后者继续拥有 rc.2 迁移；本记录拥有 0.2.1-rc.2 迁移及每一处被移除或被改动的官方表面所强迫的适配。

## Problem

集成分支声明的是 `>=0.2.0-rc.2`，而官方家族已发布 `0.2.1` 线：先是 `0.2.1-rc.1`，再是 2026-10-17 的 `0.2.1-rc.2`（预发布，tag `dsh-v0.2.1-rc.2`，commit `687f282`），受支持的宿主安装器随之移动。停在 `0.2.0` 线会让家族的可读下限指向一个当前 cohort 不再提供的宿主，这正是 [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) 存在要防止的漂移。

与 rc.2 迁移不同，这次不是纯粹的 cohort 字面量推进。`0.2.1` 线移除了家族所依赖的官方表面——runtime invariants 注册表及其 `./invariant` 伴生约定、工具呈现模式 `both`、`ConfigFormSnapshot.mode`——给 Typert gateway 请求新增了必填形态，改变了插件子路径展示元数据的读取方式，并扩展了 shell 冻结的 `staticModules` 表。同时 Models 页原生覆盖了家族 `dsh-model-capabilities` 包赖以存在的两个字段编辑器，于是一个被保留的扩展变成了重复实现。

## Decision

整个 cohort 从 `0.2.0-rc.2` 迁到 `0.2.1-rc.2`，在隔离工作树 `feat/dsh-0.2.1-alpha.5`（`C:/Users/A/Documents/ChatGPT/.worktrees/dsh-0.2.1-alpha.5/main`）中一次完成，整合之前共享 checkout 与运行中的 GUI 不受影响。它承接 [sdk-cohort-0.2.0-rc.2](2026-09-29-sdk-cohort-0.2.0-rc.2.md)：后者继续拥有 rc.2 迁移；本记录拥有 0.2.1-rc.2 迁移。`@deepseek-ai/cordis` 这次移到 `^4.0.5`、`@deepseek-ai/schemastery` 移到 `^3.18.5`——与 rc.2 迁移不同，这两条线在本线都有对应发布。

### 证据

- 官方 Release：[dsh-v0.2.1-rc.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.2)（2026-10-17 发布；面向用户的说明覆盖 DeepSeek-V4.1-Flash-1017 与 DeepSeek Search / Fetch API）。
- 官方 compare：[dsh-v0.2.0-rc.2...dsh-v0.2.1-rc.2](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.2.0-rc.2...dsh-v0.2.1-rc.2)（本次适配所回应的 baseline...target 窗口）。
- Registry：`npm view @deepseek-ai/dsh@0.2.1-rc.2` 可解析；`@deepseek-ai/dsh-invariants` 停在 `0.2.0-rc.2`——该包没有发布 `0.2.1` 线，registry 因此证实 invariants 表面是被移除而非改名。
- 直接核对已安装的 0.2.1-rc.2 类型：`@deepseek-ai/dsh-tools` 声明 `ToolPresentationMode = 'native' | 'ptc'`；`@deepseek-ai/dsh-client-ui-settings` 的 `ConfigFormSnapshot<T>` 不再携带 `mode`；`@deepseek-ai/dsh-api-gateway` 的 `InvokeRemoteRequest` 新增必填 `peer: PeerScope`（"Peer the call speaks for; every carrier and in-process caller names it explicitly"）；shell dist bundle 的冻结 `staticModules` 表新增 `zod` 与 `@tanstack/react-virtual`。

### 被移除与被改动的官方表面及家族的应对

| 删除 `ConfigFormSnapshot.mode` | shared 的 `pendingSnapshot()`（`shared/client/settings/settings-entry-form.ts`）、其生成的各包副本与测试 double 以 `mode: 'host'` 初始化 | 采用。每个源码、生成副本与测试 double 都删掉该字段；没有任何代码读它。 |

| Models 页原生编辑自定义供应商的逐模型输入类型与推理等级 | `dsh-model-capabilities` 经官方 `llm-pi-ai` 设置文档编辑 `models[].input` 与 `models[].reasoningEfforts`，另含供应商停用/启用与归档 | 作为重复实现移除。整包删除；聚合只保留 `model-capabilities` tombstone 导出并将 `@linxin666/dsh-client-ui-model-capabilities` 列入 `RETIRED_PLUGINS`（旧 profile 仍可解析，但不再挂载）。细节由 [model-capabilities-native-removal](../simplification/2026-10-17-model-capabilities-native-removal.md) 拥有，包括用户明确接受退场的供应商归档/切换能力。 |

核对后无重叠的表面：Release 说明里面向用户的条目（DeepSeek-V4.1-Flash-1017 支持、DeepSeek Search / Fetch API）触及的是家族不打补丁的官方模型与联网搜索路径；除梁神外没有家族包经由被移除的 `both` 模式注册工具；也没有其他家族包消费 `ConfigFormSnapshot.mode`。

## Alternatives considered

**停在 `0.2.0-rc.2`，等 0.2.1 线稳定。** 否决：家族下限会指向官方安装器已经离开的宿主，这正是 [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) 存在要防止的漂移，且操作者要求对 0.2.1 线做 rc.2 适配。

**把两个 invariant 伴生模块作为惰性产物继续发布。** 否决：它们注册所面向的注册表已不存在于本 cohort，伴生模块将对着宿主不再提供的服务发布 cordis 形态，家族会为一个已被移除的官方表面背负死契约。

**把 `dsh-model-capabilities` 保留为原生编辑器之上的薄皮。** 否决：原生编辑器覆盖了该包赖以存在的两个字段，包的核心面板成为重复；其剩余独特能力是带归档的供应商停用/启用，而用户明确选择退场该能力而非迁移（记录在 [model-capabilities-native-removal](../simplification/2026-10-17-model-capabilities-native-removal.md)）。

**在配置校验时直接拒绝已保存的 `both` 呈现。** 否决：`both` 是 `0.2.1` 之前的出厂默认值，任何保存过梁神设置的 profile 都在 `cordis.patch.yml` 中写入了 `presentation: both`。在 host `Config` schema 中拒绝它会使 `ctx.plugin()` 抛出 `ValidationError: expected "ptc" | "native" but got "both"`，导致整个 `@linxin666/dsh-liangshen` 插件在启动时降级；将已弃用的 `'both'` 归一化为 `'ptc'`（并在 `tool-catalog.mjs` 中告警一次，与 `ptcPresentation`、`anchorTools` 保持一致）能让既有 profile 平滑启动，同时对新编辑只提供 `'ptc'` 与 `'native'`。

**用 cast 绕过必填 gateway `peer` 以解锁 lane。** 否决：该字段是 0.2.1 连线契约的必填部分（"every carrier and in-process caller names it explicitly"），因此调用点直接写明自己的 peer——在插件 fiber 上铸出的 owner peer——而不是用 cast 把一个未经评审的身份选择发出去。

**随本 cohort 把四个卫星仓发布到 npm。** 否决：卫星仓在各自仓库内迁到 rc.2 以供市场构建与本地链接，但 SDK cohort 适配不伴随任何 npm 发布；卫星发版走各自的发布流程。

## Consequences

- 声明下限、宿主 peer、徽章、CI 与发布挂载 pin（`DSH_CLI_VERSION: 0.2.1-rc.2`）、发布冷却账本与 lockfile 全部指向 `0.2.1-rc.2`；`@deepseek-ai/cordis`（`^4.0.5`）与 `@deepseek-ai/schemastery`（`^3.18.5`）这次随线移动。
- 本 cohort 的 npm 发布最初不完整：0.2.1-rc.2 的包在第一次安装尝试时短暂 404，registry 在整合前补齐——与 rc.2 迁移为 `@deepseek-ai/dsh-client-ui-settings-account` 记录的迟到发布模式相同。安装已针对补齐后的 registry 重跑。
- `dsh-model-capabilities` 从源码树、聚合 `patchFrom`/`deps` 列表、`cordis.patch.yml`、i18n 审计包清单与 publish-prep 包表（移除后 18 个家族包）中消失；其聚合行 id 只以导出 tombstone 加生成的 `shell-metadata/` locale 文件存活，使既有 profile 仍可解析。
- 没有任何家族包声明 `./invariant` 或依赖 `@deepseek-ai/dsh-invariants`；若回归，`scripts/family-dsh-engines.test.mjs` 会失败。
- 梁神会话的连线默认为 `ptc`（收拢为 `run_code` 传输，其余工具经生成的 SDK 调用），`native` 是一行可选项；`both` 臂退出 benchmark 矩阵。
- task-board 与 remote-bridge 的 host 半区都写明必填 `peer`：`createOwnerPeer(ctx)` 在各插件 fiber 上铸出进程内 owner peer，每次 invoke 与 stream 都携带它；远程桥的 peer 只在桥自己的配对门禁之后使用，绝不接受客户端传入的 principal。
- 四个卫星仓（dsh-skins、dsh-pet、dsh-community-plugins、dsh-presets）在各自仓库迁到 rc.2；没有任何 `@linxin666/*` 版本变化，本次不发布任何内容。
