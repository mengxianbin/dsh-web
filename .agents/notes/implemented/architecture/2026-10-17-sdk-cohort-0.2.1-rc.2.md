# Agent Note: SDK cohort 0.2.1-rc.2

Status: implemented

Supersedes the runtime-invariant surface of [make each package's invariant companion match what it ships](../simplification/2026-10-10-invariant-companion-surface-honest.md) and, together with [remove dsh-model-capabilities](../simplification/2026-10-17-model-capabilities-native-removal.md), supersedes the capability-editor overlap row recorded in [sdk-cohort-0.2.0-rc.2](2026-09-29-sdk-cohort-0.2.0-rc.2.md). It keeps owning the rc.2 move; this note owns the 0.2.1-rc.2 move.

## Problem

The integration branch declared `>=0.2.0-rc.2` while the official family published the `0.2.1` line: `0.2.1-rc.1` first and `0.2.1-rc.2` on 2026-10-17 (pre-release, tag `dsh-v0.2.1-rc.2`, commit `687f282`), and the supported host installers moved with it. Staying on the `0.2.0` line would leave the family's machine-readable floor naming a host the current cohort no longer serves, the drift [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) exists to prevent.

Unlike the rc.2 move, this is not a pure cohort-literal bump. The 0.2.1 line removes official surface the family builds on — the runtime invariants registry and its `./invariant` companion convention, the `both` tool presentation mode, and `ConfigFormSnapshot.mode` — adds required shape to the Typert gateway request, changes how plugin subpath display metadata is read, and extends the shell's frozen `staticModules` table. The Models page also grew native editors for the two fields the family's `dsh-model-capabilities` package existed to edit, which turns a kept extension into a duplicate.

## Decision

The whole cohort moves from `0.2.0-rc.2` to `0.2.1-rc.2` in one change, in the isolated worktree `feat/dsh-0.2.1-alpha.5` (`C:/Users/A/Documents/ChatGPT/.worktrees/dsh-0.2.1-alpha.5/main`), so the shared checkout and the running GUI are untouched until integration. It follows [sdk-cohort-0.2.0-rc.2](2026-09-29-sdk-cohort-0.2.0-rc.2.md), which keeps owning the rc.2 move; this note owns the 0.2.1-rc.2 move and the adaptation each removed or changed official surface forced. `@deepseek-ai/cordis` moves to `^4.0.5` and `@deepseek-ai/schemastery` to `^3.18.5` this time — both publish a matching release in this line, unlike the rc.2 move.

### Evidence

- Official release: [dsh-v0.2.1-rc.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.2) (released 2026-10-17; user-visible notes cover DeepSeek-V4.1-Flash-1017 and the DeepSeek Search / Fetch APIs).
- Official compare: [dsh-v0.2.0-rc.2...dsh-v0.2.1-rc.2](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.2.0-rc.2...dsh-v0.2.1-rc.2) (the baseline...target window this adaptation answers to).
- Registry: `npm view @deepseek-ai/dsh@0.2.1-rc.2` resolves; `@deepseek-ai/dsh-invariants` stops at `0.2.0-rc.2` — the package publishes no `0.2.1` line, so the registry confirms the invariants surface was removed rather than merely renamed.
- Installed 0.2.1-rc.2 types checked directly: `@deepseek-ai/dsh-tools` declares `ToolPresentationMode = 'native' | 'ptc'`; `@deepseek-ai/dsh-client-ui-settings` `ConfigFormSnapshot<T>` no longer carries `mode`; `@deepseek-ai/dsh-api-gateway` `InvokeRemoteRequest` gains a required `peer: PeerScope` ("Peer the call speaks for; every carrier and in-process caller names it explicitly"); the shell dist bundle's frozen `staticModules` table adds `zod` and `@tanstack/react-virtual`.

## Alternatives considered

**Stay on `0.2.0-rc.2` until the 0.2.1 line stabilizes.** Rejected: the family's floor would name a host the official installers have already left, which is the drift [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) exists to prevent, and the operator asked for the rc.2 adaptation of the 0.2.1 line.

**Keep shipping the two invariant companions as inert artifacts.** Rejected: the registry they register with no longer exists in the cohort, so the companions would publish a cordis shape against a service the host no longer provides, and the family would carry a dead contract for a removed official surface.

**Keep `dsh-model-capabilities` as a thin skin over the now-native editors.** Rejected: the native editors cover the two fields the package existed for, so the package's core panel is a duplicate; its remaining unique capability was provider disable/enable with an archive, and the user explicitly chose to retire that capability rather than re-home it (recorded in [model-capabilities-native-removal](../simplification/2026-10-17-model-capabilities-native-removal.md)).

**Reject a saved `both` presentation at config validation.** Rejected: `both` was the shipped default before `0.2.1`, so any profile that ever saved LiangShen settings wrote `presentation: both` into `cordis.patch.yml`. Refusing it in the host `Config` schema fails `ctx.plugin()` with `ValidationError: expected "ptc" | "native" but got "both"` and degrades the whole `@linxin666/dsh-liangshen` plugin on startup; normalizing the deprecated `'both'` value to `'ptc'` (and warning once in `tool-catalog.mjs`, matching `ptcPresentation` and `anchorTools`) keeps existing profiles booting cleanly while only offering `'ptc'` and `'native'` for new edits.

**Patch around the required gateway `peer` with a cast to unblock the lane.** Rejected: the field is a required part of the 0.2.1 wire contract ("every carrier and in-process caller names it explicitly"), so the call site names its peer — an owner peer minted on the plugin fiber — instead of shipping an unreviewed identity choice behind a cast.

**Publish the four satellite repositories to npm with this cohort.** Rejected: the satellites move to rc.2 in their own repositories for the market build and local linking, but no npm publication happens as part of an SDK cohort adaptation; satellite releases follow their own release flow.

## Consequences

- The declared floor, the host peer, the badges, the CI and release mount pins (`DSH_CLI_VERSION: 0.2.1-rc.2`), the release-age ledger, and the lockfile all name `0.2.1-rc.2`; `@deepseek-ai/cordis` (`^4.0.5`) and `@deepseek-ai/schemastery` (`^3.18.5`) move with the line this time.
- The cohort's npm publish was initially incomplete: the 0.2.1-rc.2 packages briefly 404'd on npm during the first install attempt and the registry closed the gap before integration — the same late-publish pattern the rc.2 move recorded for `@deepseek-ai/dsh-client-ui-settings-account`. The install was re-run against the completed registry.
- `dsh-model-capabilities` is gone from the tree, the aggregate `patchFrom`/`deps` lists, `cordis.patch.yml`, the i18n audit package list, and the publish-prep package table (18 family packages after the removal); its aggregate row id survives only as an export tombstone plus generated `shell-metadata/` locale files so existing profiles keep resolving.
- No family package declares `./invariant` or depends on `@deepseek-ai/dsh-invariants`; `scripts/family-dsh-engines.test.mjs` fails if one regresses.
- LiangShen sessions now default to the `ptc` wire (`run_code` transport, other tools through the generated SDK) with `native` as the one-line opt-out; the `both` arm leaves the benchmark matrix.
- The task-board and remote-bridge host halves name the required `peer`: `createOwnerPeer(ctx)` mints an in-process owner peer bound to each plugin fiber, and every invoke and stream carries it; the remote bridge's peer is used only behind its own pairing gate and never accepts a client-supplied principal.
- The four satellite repositories (dsh-skins, dsh-pet, dsh-community-plugins, dsh-presets) move to rc.2 in their own trees; no `@linxin666/*` version changed and nothing was published from this change.
