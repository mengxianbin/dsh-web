# Agent Note: SDK cohort 0.2.0-rc.2

Status: implemented

## Problem

The integration line declared `0.2.0-rc.1` while the official family published `0.2.0-rc.2` on 2026-09-29 (npm `next`, tarballs stamped 09:40Z), and the runtime that actually hosts this repository's plugins had already moved past the declared floor: the running DeepSeek Harness desktop client bundles `@deepseek-ai/dsh-desktop-runtime@0.2.0-rc.2`, which carries `@deepseek-ai/dsh@0.2.0-rc.2` and the rest of the cohort at that version. Staying put would leave the family's machine-readable floor naming a host the running client has left, so an installing user would be told to run a version the supported client no longer serves.

Two facts shaped the move. First, this is a same-line candidate bump, not a new series: every one of the 68 `@deepseek-ai/*` packages this repository consumes publishes `0.2.0-rc.2` under the `next` dist-tag, and 67 of them differ from rc.1 only by the cohort literal in their own peer and dependency ranges. Second, the repository has no `desktop/` tree, so the packaged-desktop-runtime pin named by [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) still has nothing to move here.

## Decision

The whole cohort moves to `0.2.0-rc.2` in one change, in the isolated worktree `feat/dsh-0.2.0-rc.2-upgrade` (`/Users/zcl/code/.worktrees/dsh-web/feat-dsh-0.2.0-rc.2-upgrade`) created by `wt switch --create` from `origin/dev` (`65d1f6f4`, equal to the local `dev` tip), so the shared checkout and the running GUI are untouched until integration. It follows [sdk-cohort-0.2.0-rc.1](2026-09-28-sdk-cohort-0.2.0-rc.1.md), which keeps owning the rc.1 move and the body-mutation analysis recorded there; this note owns the rc.2 move and supersedes none of it.

### One cohort, one literal

358 occurrences across 48 files, plus `pnpm-lock.yaml`: the sixteen family manifests, the plugin scaffold, the shared workspace package, the `dsh.engines.dsh` floors with their identical `@deepseek-ai/dsh` host peers, the root manifest's own SDK devDependencies, the release-age exclusion ledger (68 entries) and the two `packageExtensions` keys re-keyed to the new cohort, the root README badge in both languages (the shields form `0.2.0--rc.2`), the CI and release mount-smoke pins, the cohort literals in `shared/web-platform.ts`, `shared/tests/web-platform.spec.ts`, `tests/e2e/mount.e2e.ts`, `scripts/rollout-verify.test.mjs`, `scripts/aggregate.test.mjs`, `packages/dsh-plugin-manager/tests/gateway-jobs.spec.ts` and `packages/dsh-liangshen/tests/benchmark-live-run.test.ts`, and the cohort prose in `docs/publish-prep.md`, `docs/plugins.md`, `packages/dsh-web-all/aggregate.yml`, `packages/dsh-i18n/AGENTS.md`, `packages/dsh-remote-web-ui/AGENTS.md` and the six package README pairs (with their pairing records re-recorded). Historical narratives that name earlier cohorts — the rc.1 note and its sidecar, `docs/release-notes/v0.4.4.md`, the v0.4.4 archive snapshot, and the two notes that record verification runs performed on the rc.1 host — are not rewritten.

`@deepseek-ai/cordis` (4.0.4) and `@deepseek-ai/schemastery` (3.18.4) do not move: neither publishes a `0.2.0-rc.2`, their lines are independent, and the cohort's own peers still name them at those versions.

## Alternatives considered

**Stay on `0.2.0-rc.1` until `0.2.0` is stable.** Rejected: the running desktop client already serves rc.2, so the family's floor would name a host the supported client has left, which is exactly the drift [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) exists to prevent, and the operator asked for the rc.2 adaptation.

**Move only the SDK devDependency ranges and leave the floor, badge and mount pins on rc.1.** Rejected: the floor, host peer, badge and mount pin are one contract; splitting them across two candidate versions is the state that note forbids.

**Use the new `MenuGroup` primitive somewhere so the cohort's added export is "adopted".** Rejected: no family surface renders a grouped sticky menu, so adopting it would add UI surface for the sake of the export list. Deep adaptation means removing duplicates, not manufacturing consumers for additive exports.

**Delete the family update-check block because the official page now advises upgrades.** Rejected on evidence: the official change adds advisory strings, while the registry comparison and the one-click update stay family-owned; deleting ours would ship a capability regression for a copy change.

**Refresh the local profiles in this change.** Rejected: the shadow-copy check reports no cross-cohort mismatch, profiles are materialized from their own lockfiles, and the skill that governs this flow forbids installs against a running profile instance. The profile tree is left alone.

## Consequences

- The declared floor, the host peer, the badges, the CI/release mount pins and the release-age ledger all name `0.2.0-rc.2`, and the lockfile resolves all 51 `@deepseek-ai/dsh-*` keys at exactly that version with zero rc.1 entries left. The lockfile diff is symmetric (815 insertions, 815 deletions) and contains no package movement outside the cohort.
- The running DeepSeek Harness desktop client already serves 0.2.0-rc.2, so the family and the client that loads it are on the same line for the first time since the rc.1 move; `pnpm install --frozen-lockfile --ignore-scripts` passes the supply-chain policy check against the rc.2 exclusion ledger.
- The Homebrew `dsh` CLI on this machine is still npm `latest` at `0.1.7-rc.2`, below the new floor. Moving the global CLI is a `dsh-upgrade` concern, not part of an SDK cohort move; until it happens, a profile driven by that CLI sits below the family's declared floor. This is recorded open rollout work. There is no packaged-desktop pin to move in this repository, and therefore no desktop re-release pending from this change.
- The local `desktop` profile keeps real copies of `@deepseek-ai/cosmokit` and `@deepseek-ai/schemastery` at the host's own version — the same latent module-identity hazard the cohort check reports as a warning, unchanged by this move and harmless while the versions agree.
- `@deepseek-ai/dsh-user-questions` now requires `schemastery` and `zod` for its timed-wait mode. Nothing in this repository resolves that package, so no dependency was added.
- The cohort's npm publish was initially incomplete: `@deepseek-ai/dsh-web-app@0.2.0-rc.2` declares a hard dependency on `@deepseek-ai/dsh-client-ui-settings-account@0.2.0-rc.2`, and that version was absent for the first ~20 minutes, so `npm install -g @deepseek-ai/dsh@0.2.0-rc.2` failed with `ETARGET` — exactly the step the CI and release mount-smoke lanes run. Upstream published it before integration: a closure walk from `@deepseek-ai/dsh@0.2.0-rc.2` now resolves 252 cohort packages with none missing, the same install command completes, and the mount smoke passes in that registry form.
- No package was published, no version of any `@linxin666/*` package changed, and no DSH source checkout was read into or modified.
